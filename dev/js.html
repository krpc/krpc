JavaScript#

This guide describes how to install the JavaScript client, and the features it provides. The Client API Reference describes each function and class.

The client runs in a web browser and in Node.js 22 or later.

Installing the Library#

The library is the @krpc-org/krpc package on npm, which can also be downloaded from GitHub. To install it with npm:

npm install @krpc-org/krpc

The package is a set of ES modules, and depends on the @bufbuild/protobuf and acorn packages. A web page loads it through a bundler, such as esbuild or Vite, which resolves those dependencies. To bundle a script main.js and the client into one file with esbuild:

npm install esbuild
npx esbuild main.js --bundle --format=esm --outfile=main.bundle.js

Then load it from the page with <script type="module" src="main.bundle.js"></script>. Node.js runs a script that imports the package without a bundler.

Connecting to the Server#

The game must be running with the server started. The Server Plugin in the getting started guide shows how to install and start it.

The client connects over WebSockets, the protocol a web browser can use. The game has a “Protobuf over WebSockets” server on port 50001 by default. Settings saved by a kRPC release before 0.8 have only the TCP/IP server, so add a server in the server window, with “Protobuf over WebSockets” as its protocol.

connect() connects to the server, and returns a Connection. You make every call through this object. The following connects to a server with the default settings, address 127.0.0.1 and port 50001, and prints its version:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const status = await conn.krpc.getStatus();
console.log(status.version);

connect() also takes a name for the connection, and the address and port of the server. These match the address and port shown in the server window. The name appears in the server window in the game:

import { connect } from "@krpc-org/krpc";

const conn = await connect({
  name: "My Example Program",
  address: "192.168.1.10",
  port: 1000,
});
const status = await conn.krpc.getStatus();
console.log(status.version);

WebSockets works over a network, so your program can run on a different machine from the game.

Note

A server with “Auto-accept new clients” turned off answers only once the player approves the connection in game. The connection fails after 5 seconds by default. Pass Infinity as the handshakeTimeout to wait for the player.

Note

A browser blocks a page served over https:// from connecting to a ws:// address. Open the page over http://, or as a local file.

Closing the Connection#

Connection.close() closes a connection:

import { connect } from "@krpc-org/krpc";

const conn = await connect({ name: "My Example Program" });
const status = await conn.krpc.getStatus();
console.log(status.version);
await conn.close();

Calling Remote Procedures#

The server provides procedures for your program to call, grouped into services.

The following gets the active vessel, an object of the SpaceCenter.Vessel class. It sets the vessel’s name, then prints its altitude:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();

await vessel.setName("My Vessel");

const flightInfo = await vessel.flight();
console.log(await flightInfo.getMeanAltitude());

Each service is a property of the connection, such as conn.spaceCenter. A property is a pair of methods, such as vessel.getName() and vessel.setName(name).

Every call returns a Promise, which resolves once the server responds. Several calls can be in flight at once, and each resolves with its own result. The following reads three values, without waiting for each response before sending the next call:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();
const flightInfo = await vessel.flight();

// The three calls are in flight at once
const [altitude, speed, pitch] = await Promise.all([
  flightInfo.getMeanAltitude(),
  flightInfo.getSpeed(),
  flightInfo.getPitch(),
]);
console.log(altitude, speed, pitch);

Default and Named Arguments#

A procedure can give some of its arguments default values. Pass undefined, or leave out the trailing arguments, to take the default. A plain object after the other arguments passes arguments by name. The following launches a vessel without recovering the vessel on the launch pad, and leaves the crew argument before it at its default:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
await conn.spaceCenter.launchVessel("VAB", "My Rocket", "LaunchPad", {
  recover: false,
});

Passing an argument both by position and by name, or naming an argument the procedure does not have, rejects with a TypeError.

Values#

Procedures take and return JavaScript values, such as number, string, Array and Map, and null for a null. The services also define their own types:

  • A class is a remote object, such as a SpaceCenter.Vessel.

  • A structure is a frozen object of the service’s class, such as conn.spaceCenter.BoundingBox, with a property for each field. Make one with new, passing an object of the fields.

  • An enumeration value is a RemoteEnum, such as conn.spaceCenter.VesselSituation.orbiting, or a RemoteFlags for a flags enumeration.

The equals() function compares two values by their contents, such as two structures.

Flags Enumerations#

A flags enumeration, such as MapFilterType, holds any combination of its values. You combine values with union, and test for one with contains:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const MapFilterType = conn.spaceCenter.MapFilterType;

// Show only probes and ships in map mode
await conn.spaceCenter.setMapFilter(
  MapFilterType.probes.union(MapFilterType.ships),
);

// Check whether map mode shows debris
const filter = await conn.spaceCenter.getMapFilter();
console.log(filter.contains(MapFilterType.debris));

// Show debris as well
await conn.spaceCenter.setMapFilter(filter.union(MapFilterType.debris));

intersection and difference give the other combinations of two values. Each combination is one object, so combinations compare with ===.

Types Without a Connection#

The package exports each service of a kRPC release, with its enumerations, structures and exception classes. You can then use a value before you connect, such as in a default argument:

import { connect, SpaceCenter } from "@krpc-org/krpc";

/** Points a vessel with its SAS, prograde by default.
 * @param {SpaceCenter.Vessel} vessel
 * @param {SpaceCenter.SASMode} mode */
async function point(vessel, mode = SpaceCenter.SASMode.prograde) {
  const control = await vessel.getControl();
  await control.setSAS(true);
  await control.setSASMode(mode);
}

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();
await point(vessel);

// The connection's values are the package's values
const control = await vessel.getControl();
console.log((await control.getSASMode()) === SpaceCenter.SASMode.prograde);

When the server defines a type as the package does, the connection uses the package’s type. Its values then compare with ===, and instanceof works with the package’s classes. A connection to a server with a different definition builds its own type. A value of the package’s enumeration still passes as an argument, by its number, and equals() compares values of the two by number.

Using the Client in a Web Page#

The following script shows the altitude of the active vessel in a page. A stream with a callback updates it each time it changes, at most 10 times a second:

import { connect } from "@krpc-org/krpc";

const conn = await connect({ name: "Dashboard" });
const vessel = await conn.spaceCenter.getActiveVessel();
const flightInfo = await vessel.flight();
const altitude = await conn.addStream(() => flightInfo.getMeanAltitude());
await altitude.setRate(10);

// Show the altitude in the page's <span id="altitude"> as it changes
const element = document.getElementById("altitude");
altitude.addCallback((value) => {
  element.textContent = `${value.toFixed(0)} m`;
});

Bundle the script for the page as shown in Installing the Library.

Note

Any page open in the browser can connect to a server it can reach. A server with “Auto-accept new clients” turned off asks the player to approve each connection.

See also

The Web Browser Control Panel tutorial builds a complete page.

Handling Errors#

A procedure that fails on the server rejects its Promise with an error. The following catches the error from loading a save that does not exist:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
try {
  await conn.spaceCenter.load("missing");
} catch (error) {
  if (!(error instanceof conn.krpc.ArgumentException)) {
    throw error;
  }
  console.log(`Failed to load the save: ${error.description}`);
}

The error you catch depends on the error on the server:

  • A standard error, such as an invalid argument, is a class that extends only the matching JavaScript error. A missing save is conn.krpc.ArgumentException, which extends TypeError.

  • An error particular to a service is a class of that service, such as conn.krpc.ObjectDestroyedException, which extends ServerError.

  • Any other error is a ServerError, with the server’s description as its message.

The client’s own errors each extend RemoteError, as ServerError does:

  • ConnectionError for a failed connection attempt. When the server refuses the connection, its status names the status the server gave, such as DENIED. When the server ends the connection, its reason names the reason, such as SERVER_STOPPED. A call made once the connection has closed or failed rejects with it too.

  • EncodingError for a malformed result from the server.

  • StreamError for a stream that has been removed or cannot be added, and for Stream.value before the first value. See Stream Endings.

A call with an argument of the wrong type rejects with a TypeError, and one with a number outside the range of its type with a RangeError. These errors and the standard errors, such as conn.krpc.ArgumentException, do not extend RemoteError.

Remote Objects#

Many procedures return an object identifying something in the game, such as a vessel or a part. The object holds no copy of the game’s state. It is just a reference to it. Each call through it reads the game as it is now:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();
const flightInfo = await vessel.flight();

// Each read gets the current altitude from the game
console.log(await flightInfo.getMeanAltitude());
await new Promise((resolve) => setTimeout(resolve, 1000));
console.log(await flightInfo.getMeanAltitude());

// Two results for the same vessel are the same object
console.log(vessel === (await conn.spaceCenter.getActiveVessel()));

A connection returns one JavaScript object for each object on the server, so two results for the same thing in the game compare equal with ===. An object works as a Map key or a Set element.

Once the thing an object identifies is destroyed, such as a part that explodes, each call through it rejects with conn.krpc.ObjectDestroyedException.

See also

Object Lifetime describes how each kind of object behaves in more detail.

Streaming Data#

A common use of kRPC is to read data from the game continuously. Calling a procedure in a loop sends a request and waits for its response each time. A stream is more efficient. The server runs the call repeatedly, and sends your program the result each time it changes:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();
const flightInfo = await vessel.flight();
const altitude = await conn.addStream(() => flightInfo.getMeanAltitude());

// Prints the altitude each time it changes
console.log(await altitude.get());
while (true) {
  await altitude.wait();
  console.log(altitude.value);
}

Connection.addStream() takes a function that returns one call, such as () => flightInfo.getMeanAltitude(), and returns a Promise of a Stream. The client runs the function to build the call, without sending it. The stream’s type comes from the call, so TypeScript types altitude as a Stream<number>.

Stream.get() waits for the stream’s first value, and Stream.value is its latest value. Stream.wait() waits for the next value. It takes a timeout in milliseconds, and resolves with false when it elapses before an update.

Each call to Connection.addStream() creates another stream. A stream of a procedure with no return value, such as a property setter, runs the call on each update for its effects. Its value is undefined.

A stream runs until you remove it with Stream.remove(), or the connection closes. It keeps running after your program drops its last reference to it, so remove a stream you no longer need. An await using declaration removes a stream at the end of its block. It needs Node.js 24 or a recent browser, or TypeScript to compile it:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();
const flightInfo = await vessel.flight();
{
  await using altitude = await conn.addStream(() =>
    flightInfo.getMeanAltitude(),
  );
  console.log(await altitude.get());
}
// The stream was removed at the end of the block

By default, the server sends a stream’s value each time it changes. Stream.setRate() limits how many times a second the stream updates, as in the web page example.

Callbacks#

A callback is a function the client calls with each new value of a stream. The following adds two callbacks to a stream of the abort button:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();
const control = await vessel.getControl();
const abort = await conn.addStream(() => control.getAbort());

abort.addCallback((value) =>
  console.log("Abort 1 called with a value of", value),
);
abort.addCallback((value) =>
  console.log("Abort 2 called with a value of", value),
);

A callback added to a stream that already has a value is called with that value before Stream.addCallback() returns. It is then called with each new value, in order. The client calls it once it has handled the message holding the value, so a callback can make calls and await them.

A callback that returns a Promise is not called again until the Promise settles. It is then called with the latest value, and skips the values in between. An error a callback throws goes to reportError in a web page, or console.error in Node.js. The stream keeps running.

Stream Endings#

A stream ends when its procedure throws an exception, when the server removes it, when you remove it, or when the connection closes. Stream.get(), Stream.value and Stream.wait() then throw the error that ended it. The following streams the temperature of a part until the part is destroyed:

import { connect, KRPC } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();
const parts = await vessel.getParts();
const root = await parts.getRoot();
const temperature = await conn.addStream(() => root.getTemperature());

try {
  while (true) {
    await temperature.wait();
    console.log("Temperature", temperature.value);
  }
} catch (error) {
  if (!(error instanceof KRPC.ObjectDestroyedException)) {
    throw error;
  }
  console.log("The part was destroyed");
}

The error is the one the procedure threw, or one of the following:

  • StreamError when you or the server remove the stream.

  • ConnectionError when the connection closes or fails.

An exception for an object that is not loaded, or for a procedure not available in the current game scene, does not end the stream. It pauses the stream’s updates, and the stream keeps its last value. The updates resume once the object or the scene is available.

See also

Object Lifetime describes when each kind of object is not loaded, and how streams behave around a load.

Stream.addEndCallback() adds a callback that is called once when the stream ends, with the error:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();
const parts = await vessel.getParts();
const root = await parts.getRoot();
const temperature = await conn.addStream(() => root.getTemperature());

temperature.addCallback((value) => console.log("Temperature", value));
temperature.addEndCallback((error) =>
  console.log("The stream ended:", error.message),
);

Events#

An event tells your program when something happens in the game. A procedure that returns an event, such as one from a mod’s service, gives you an Event. So does Connection.addEvent(), for a server side function:

const event = await conn.myMod.onDocked();
await event.wait();

Event.wait() waits for the event to fire. It returns at once if the event has fired since your last wait, so a firing between two waits is not missed. Event.addCallback() adds a function to call each time the event fires.

An event ends in the same ways as a stream. When the event fires just before the server ends it, your next wait returns for that firing first. Removing the event or closing the connection ends it at once. Event.stream is the event’s stream, of a boolean that is true once the event has fired.

Server Side Functions#

A server side function runs inside the game. The client compiles a JavaScript function into one, and the server runs it there. The following reads the vessel’s altitude and speed in one physics tick:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();
const body = await (await vessel.getOrbit()).getBody();
const flight = await vessel.flight(await body.getReferenceFrame());

// The altitude the vessel would coast up to with no drag, from its altitude
// and speed
const gravity = 9.81;
const apex = await conn.run(
  ({ flight, gravity }) =>
    flight.meanAltitude + flight.speed ** 2 / (2 * gravity),
  { flight, gravity },
);
console.log(`Apex: ${apex.toFixed(1)} m`);

The function is written as it runs on the server. A property is read as a property, as in flight.meanAltitude, and a method returns its value. The server side functions guide describes what functions are for, and how the server runs them.

Captured Values#

The function reads values from your program only through its first parameter, an object pattern such as ({ flight, gravity }). The client passes it the object given after the function. A minifier keeps the keys of the pattern, so a compiled function survives one. A name the function reads that is not captured is a CompilationError:

import { CompilationError, connect } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();
const limit = 70000;

try {
  // limit is read from the program, so it must be captured
  await conn.compile(({ vessel }) => vessel.flight().meanAltitude > limit, {
    vessel,
  });
} catch (error) {
  if (error instanceof CompilationError) {
    console.log(error.message);
  }
}

Each captured value is used as follows:

  • A remote object or a service makes its members calls in the function, made again on each evaluation. A service is captured as conn.spaceCenter, or through the connection, as conn.

  • A number, bigint, string, boolean, null or enumeration value is a constant.

  • A plain object, a generated module such as SpaceCenter, and the object of an enumeration’s values are read on the client. SpaceCenter.SASMode.prograde is a constant.

  • Any sub-expression of constants, such as gravity * 2, is computed on the client, with the result JavaScript gives.

A function with no captures takes no parameters, or names its first one, such as _, and does not read it. The builtins Math, console, Number, String, Boolean, BigInt, undefined, NaN and Infinity need no capture.

What a Function Can Contain#

A compiled function is an arrow function, a function expression or a method. Its body holds statements, collections and local functions, as in your program:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();

// The engines with fuel, by title, and the total thrust of those firing
const report = await conn.run(
  ({ vessel }) => {
    const titles = new Set();
    let thrust = 0;
    for (const engine of vessel.parts.engines) {
      if (!engine.hasFuel) {
        continue;
      }
      titles.add(engine.part.title);
      thrust += engine.thrust;
    }
    return `${Array.from(titles).join(", ")}: ${thrust} N`;
  },
  { vessel },
);
console.log(report);

The following compile to the server’s operations:

  • Property reads and assignments, and calls of methods and static methods, with arguments by name as a last object, as in the client’s own API. Destructuring reads properties too.

  • Arithmetic, comparisons, !, &&, ||, ??, ?., ?: and template literals.

  • The bitwise operators, on numbers and on the values of a flags enumeration, which also have union, intersection, difference and contains.

  • const and let, if, switch, while, do, for, for...of, break, continue and return, assignments, compound assignments, ++ and --. A declaration in a case goes in a block.

  • Arrays, new Set and new Map. An array is a tuple where the position takes a tuple, such as a vector argument, and a list otherwise. A captured array, Set or Map is a constant.

  • The array members length, indexing, at, map, filter, some, every, find, findIndex, includes, indexOf, reduce, slice, concat, join, toSorted, toReversed, push, pop and assignment to an element. toSorted takes a comparator that subtracts a number, such as (a, b) => a.mass - b.mass.

  • The Set and Map members has, add, get, set, delete, clear, size, keys, values and entries, and Array.from.

  • The fields of a structure, and new of a structure’s class with an object of its fields.

  • The string members length, indexing, at, slice, substring, toUpperCase, toLowerCase, trim, trimStart, trimEnd, includes, startsWith, endsWith, indexOf, replaceAll and split, and String(x). The replacement of replaceAll is a constant with no $ pattern.

  • The Math functions with a StdLib procedure, Number.isNaN and Number.isFinite.

  • console.log, which writes a line to the game’s log with StdLib.print().

  • throw new Error(message), TypeError, RangeError and a service’s exception class, and try, catch and finally.

The values keep their JavaScript meaning:

  • A number is a double. Arithmetic on numbers is in double precision, so 7 / 2 is 3.5. The bitwise operators convert their operands to 32-bit integers, as JavaScript does. A number passed as an integer argument is converted toward zero.

  • A bigint is a 64-bit integer, so 7n / 2n is 3n. Mixing a number and a bigint is a CompilationError.

  • Truth is JavaScript’s. 0, NaN, "" and null are false.

  • Null takes the type of the value beside it, such as the other branch of ?:. Arithmetic on a value that can be null is a CompilationError. Give a value for null with ??.

  • Compare a server value with == null or != null. The server has one null, so === null and === undefined are a CompilationError.

  • An empty array, Set or Map, and null, take their type from a later use, such as a push or an assignment. With no such use, give one a type with cast, such as t.list(t.double).cast([]) with the types value captured as t.

  • A function that returns a value returns one on every path, and a variable is read only where every path to the read assigns it.

  • A Set or a Map is the server’s, a .NET HashSet or Dictionary. After a delete, its order can differ from the order of insertion.

  • A number converts to a string as the server formats it, which can differ from JavaScript in the last digits.

Local functions are called as in JavaScript, and passed by name to the array methods. Each parameter takes the one type that fits the arguments of every call. A function cannot call itself, and reads the variables it uses when called, so every path to each call assigns them.

Exceptions reach a catch with only their message, as e.message. A handler that starts with if (e instanceof RangeError) catches each exception the client maps to a RangeError, and the same holds for TypeError and a service’s exception class. An else that is throw e leaves the other exceptions uncaught. A thrown Error becomes KRPC.Error on the server, a TypeError becomes KRPC.ArgumentException, and a RangeError becomes KRPC.ArgumentOutOfRangeException.

State between evaluations. A captured plain object whose property the function assigns, or changes with push and the like, keeps that property on the server between evaluations. The property starts as it is when the function is compiled, and your program’s object keeps its value:

const state = { updates: 0 };
const stream = await conn.addStream(
  ({ vessel, state }) => {
    if (vessel.thrust > 0) {
      state.updates += 1;
    }
    return state.updates;
  },
  { vessel, state },
);

Any other construct is a CompilationError that names it, with its line and column in the function’s source. The client loads the compiler the first time you compile a function, so a web page that never compiles one does not load it.

Note

A transpiler that targets an older version of JavaScript rewrites ?., ?? and arrow functions into code the compiler rejects. Target ES2020 or later. A coverage tool that instruments the source, such as Istanbul, also changes the function. V8 coverage, as c8 and Vitest use by default, does not.

Types of a Compiled Function#

TypeScript checks the body of a compiled function as it runs on the server. A captured object has its server form, in which a property is a property and a method returns its value, as flight.meanAltitude. A property you can assign is writable. The value of the function returns to your program as its client form:

const vessel = await conn.spaceCenter.getActiveVessel();
// A number, read in one physics tick
const mass = await conn.run(({ vessel }) => vessel.mass, { vessel });
// A SpaceCenter.Part, an object of your program
const root = await conn.run(({ vessel }) => vessel.parts.root, { vessel });

A function compiled with parameters checks the arguments of run, and a stream of its value has its type. The generated module of each service declares the server forms, in its Server namespace. The same checks apply to JavaScript with // @ts-check.

Running a Function#

Connection.run() compiles a function with no parameters and runs it once. The server runs the whole function within one physics tick, so every value it reads comes from the same moment in the game. In the first example, the altitude and the speed are consistent with each other, which two separate calls cannot guarantee.

A function takes arguments through the parameters after its captures. Connection.compile() compiles it once, with a type for each of those parameters, and Connection.run() passes the arguments:

import { connect, types } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();

// A function of the vessel's mass and a mass to add, in kilograms
const ratio = await conn.compile(
  ({ vessel }, payload) => (vessel.mass + payload) / vessel.mass,
  { vessel },
  [types.double],
);

for (const payload of [100, 500, 1000]) {
  console.log(`${payload} kg: ${await conn.run(ratio, payload)}`);
}

The types values name the types: types.double, types.float, types.int32, types.uint32, types.int64, types.uint64, types.bool, types.string and types.bytes, types.nullable(T), and a service’s class, such as conn.spaceCenter.Vessel. Compile a function once and run it many times, as each compile builds the function again on the server.

Function Streams and Events#

Connection.addEvent() adds an event that fires when a function’s value becomes true. Connection.addStream() streams a function’s value:

import { connect } from "@krpc-org/krpc";

const conn = await connect();
const vessel = await conn.spaceCenter.getActiveVessel();
const flight = await vessel.flight();

// An event that fires when the vessel climbs above 1000 meters
const event = await conn.addEvent(
  ({ flight }) => flight.meanAltitude > 1000,
  { flight },
);
await event.wait();
console.log("Altitude reached 1000m");

// A stream of the altitude in kilometers
const kilometers = await conn.addStream(
  ({ flight }) => flight.meanAltitude / 1000,
  { flight },
);
console.log(`Altitude: ${(await kilometers.get()).toFixed(3)} km`);

The server computes the function on each stream update. A function of a stream or an event takes no parameters, and makes a call, as a function of constants has the same value on every update.

Deprecated Members#

A member of a service can be deprecated, when a newer member replaces it. A deprecated member still works, but may be removed in a future release, so move to its replacement.

The API reference and the TypeScript declarations mark it as @deprecated, and name the replacement. A use of it emits a warning naming the replacement, once per member on a connection. The warning is a DeprecationWarning in Node.js, and a console warning in a web browser.

Service Stubs#

When you connect, the client builds every service from the service definitions the server sends, so the services match the server you connect to, whatever its version. The package also holds TypeScript declarations of the services a kRPC release ships, which give your editor the types and documentation of every procedure, class and value. They type-check JavaScript as well as TypeScript, for example with // @ts-check at the top of a script. Their enumerations, structures and exceptions are values too, which you can use without a connection.

A service from another mod has no declarations in the package. You can generate a module for it with krpc-clientgen. Without one, its members have no static types, and TypeScript reaches it through DynamicConnection:

import { connect, type DynamicConnection } from "@krpc-org/krpc";

const conn = (await connect()) as DynamicConnection;
await conn.myMod.doSomething();

Client API Reference#

@krpc-org/krpc.connect(options)#

Connects to a kRPC server over WebSockets, and builds its services.

Arguments:

  • options.name – A name for the connection, shown in the server window in the game. Defaults to "".

  • options.address – The address of the server, as a host name or an IP address. Defaults to "127.0.0.1".

  • options.port – The port of the server. Defaults to 50001.

  • options.handshakeTimeout – How many milliseconds to wait for the server to accept the connection. Defaults to 5000. Infinity waits indefinitely, such as for a server that asks the player to approve each connection.

Returns:

A Promise of the Connection.

Rejects with a ConnectionError if the connection fails or the server refuses it, and with a RangeError for a timeout that is not positive.

@krpc-org/krpc.getObjectId(obj)#

The identifier of a remote object on the server, e.g. to pass to KRPC.Expression.constantObject. Throws a TypeError if the object is null.

@krpc-org/krpc.equals(a, b)#

Whether two values are equal. Objects compare by the object on the server, structures, arrays and bytes item by item, sets and maps by their members, and other values with ===.

class @krpc-org/krpc.Connection()#

A connection to the server, with a property for each of the server’s services. Obtain one by calling connect().

Connection.close()#

Closes the connection. Each call waiting for a response rejects with a ConnectionError, and each stream ends with one. Closing a connection that is already closed does nothing.

Connection.addStream(call, captures)#

Adds a stream of a call, or of the value of a server side function.

Arguments:

  • call – A function that returns one call of a procedure, method or property getter, such as () => flight.getMeanAltitude(). The client runs it to build the call, which it does not send. Or a KRPC.Expression with no parameters, or a function to compile, with captures.

  • captures – The captured values of a function to compile.

Returns:

A Promise of the Stream.

Rejects with a StreamError for a procedure that returns an event, with a TypeError for a function that does not return one call, or a server side function with parameters, and with a CompilationError for a function that does not compile.

Connection.addEvent(fn, captures)#

Adds an event that fires when the value of a server side function becomes true, and each time it becomes true again.

Arguments:

  • fn – A KRPC.Expression of a boolean, with no parameters, or a function to compile that returns a boolean.

  • captures – The captured values of a function to compile, if it has any.

Returns:

A Promise of the Event.

Connection.getCall(call)#

The call a function returns, as a ProcedureCall message for KRPC.Expression.call.

Arguments:

  • call – A function that returns one call, as for addStream(). The client runs it to build the call, which it does not send.

Throws a TypeError for a function that does not return one call.

Connection.getCallTemplate(member)#

The call template of a member, a ProcedureCall message that names the procedure and carries no arguments, for KRPC.Expression.callWithArguments to supply each one.

Arguments:

  • member – A member function, reached through its class or service with no instance, such as Engine.prototype.getHasFuel, Engine.staticMethod or conn.spaceCenter.launchVessel.

Throws a TypeError for a function that is not a member of a service or a class. The member itself, passed where a call is expected, is converted to its call template. Functions and Collections uses a call template.

Connection.compile(fn, captures, parameters)#

Compiles a JavaScript function into a server side function, and compiles a server side function on the server, so that its first run is as fast as later ones.

Arguments:

  • fn – A KRPC.Expression, or a function to compile.

  • captures – The captured values of a function to compile, if it has any.

  • parameters – The type of each parameter of a function to compile, after its captures, such as [types.double].

Returns:

A Promise of the KRPC.Expression.

Rejects with a CompilationError for a function that does not compile.

Connection.run(fn, ...args)#

Runs a server side function once, within a single physics tick.

Arguments:

  • fn – A KRPC.Expression, or a function to compile with no parameters.

  • args – The arguments, one for each of the function’s parameters, in order. For a function to compile, its captured values, if it has any.

Returns:

A Promise of the function’s value, or of undefined for a function with no value.

Rejects with a TypeError for the wrong number of arguments, or an argument of the wrong type, with a CompilationError for a function that does not compile, and with the error the function throws.

Connection.addUpdateCallback(callback)#

Adds a function to call once for each stream update message from the server, after the callbacks of its streams.

Connection.removeUpdateCallback(callback)#

Removes a function added with addUpdateCallback().

Connection.krpc#

The KRPC service, providing the server’s basic functionality. Each of the server’s other services is a property too, such as spaceCenter.

class @krpc-org/krpc.Stream()#

A stream of a call, which the server repeats, sending each new value. Obtain one by calling Connection.addStream().

Stream.get()#

The stream’s latest value. Waits for the first value.

Returns:

A Promise of the value. Rejects with the error that ended the stream.

Stream.value#

The stream’s latest value. Throws a StreamError before the first value, and the error that ended the stream once it has ended.

Stream.wait(timeout)#

Waits for the stream’s next value.

Arguments:

  • timeout – The time to wait, in milliseconds. Leave it out, or pass Infinity, to wait indefinitely.

Returns:

A Promise of true on an update, or false once the timeout elapses. Rejects with the error that ends the stream, and with a RangeError for a negative or NaN timeout.

Stream.rate#

The most times a second the server sends the stream’s value. Zero means no limit.

Stream.setRate(rate)#

Sets the most times a second the server sends the stream’s value. Zero means no limit.

Returns:

A Promise that resolves once the server has the rate.

Stream.addCallback(callback)#

Adds a function to call with each new value. A stream that has a value calls it with that value before this returns. A callback that returns a Promise is not called again until it settles.

Stream.removeCallback(callback)#

Removes a function added with addCallback().

Stream.addEndCallback(callback)#

Adds a function to call once when the stream ends, with the error that ended it. A stream that has ended calls it before this returns.

Stream.removeEndCallback(callback)#

Removes a function added with addEndCallback().

Stream.remove()#

Removes the stream, and calls its end callbacks. Reads and waits then throw a StreamError. Removing a stream that has ended does nothing.

Returns:

A Promise that resolves once the server has removed the stream.

class @krpc-org/krpc.Event()#

An event, which fires each time its stream’s value becomes true. A procedure that returns an event gives one, as does Connection.addEvent().

Event.wait(timeout)#

Waits for the event to fire. Resolves at once for a firing since the last wait.

Arguments:

  • timeout – The time to wait, in milliseconds. Leave it out, or pass Infinity, to wait indefinitely.

Returns:

A Promise of true when the event fires, or false once the timeout elapses. Rejects with the error that ends the event.

Event.addCallback(callback)#

Adds a function to call each time the event fires. It is called before this returns for a firing since the last wait that no callback has been called for.

Event.removeCallback(callback)#

Removes a function added with addCallback().

Event.addEndCallback(callback)#

Adds a function to call once when the event ends, with the error that ended it.

Event.removeEndCallback(callback)#

Removes a function added with addEndCallback().

Event.remove()#

Removes the event, and calls its end callbacks.

Event.stream#

The event’s Stream, of a boolean that is true once the event has fired.

The type of a Connection with a property for every service the server has, such as a service from another mod. A TypeScript type only, with no static types for the services’ members.

The base class of the errors the client throws and rejects with.

A procedure that threw an exception on the server, with no JavaScript error for it. The class of each such exception a service lists extends it.

The service that lists the exception, or "".

The name of the exception, or "".
