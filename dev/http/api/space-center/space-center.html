Service#

Provides functionality to interact with Kerbal Space Program. This includes controlling the active vessel, managing its resources, planning maneuver nodes and auto-piloting.

GET /space-center/expansions#

The names of the installed expansions, for example "Serenity" (Breaking Ground) or "MakingHistory" (Making History).

Response JSON Object:

  • value (list<string>)

GET /space-center/science#

The current amount of science.

Response JSON Object:

  • value (float)

GET /space-center/funds#

The current amount of funds.

Response JSON Object:

  • value (double)

GET /space-center/reputation#

The current amount of reputation.

Response JSON Object:

  • value (float)

GET /space-center/active-vessel#

The currently active vessel.

Response JSON Object:

  • value (SpaceCenter.Vessel?)

PUT /space-center/active-vessel#

The currently active vessel.

Request JSON Object:

  • value (SpaceCenter.Vessel?) – The new value.

GET /space-center/vessels#

A list of all the vessels in the game.

Response JSON Object:

  • value (list<SpaceCenter.Vessel>)

GET /space-center/launch-sites#

A list of available launch sites.

Response JSON Object:

  • value (list<SpaceCenter.LaunchSite>)

GET /space-center/bodies#

A dictionary of all celestial bodies (planets, moons, etc.) in the game, keyed by the name of the body.

Response JSON Object:

  • value (dictionary<string, SpaceCenter.CelestialBody>)

GET /space-center/target-body#

The currently targeted celestial body.

Response JSON Object:

  • value (SpaceCenter.CelestialBody?)

PUT /space-center/target-body#

The currently targeted celestial body.

Request JSON Object:

  • value (SpaceCenter.CelestialBody?) – The new value.

GET /space-center/target-vessel#

The currently targeted vessel.

Response JSON Object:

  • value (SpaceCenter.Vessel?)

PUT /space-center/target-vessel#

The currently targeted vessel.

Request JSON Object:

  • value (SpaceCenter.Vessel?) – The new value.

GET /space-center/target-docking-port#

The currently targeted docking port.

Response JSON Object:

  • value (SpaceCenter.DockingPort?)

PUT /space-center/target-docking-port#

The currently targeted docking port.

Request JSON Object:

  • value (SpaceCenter.DockingPort?) – The new value.

POST /space-center/clear-target#

Clears the current target.

POST /space-center/launchable-vessels#

Returns a list of vessels from the given craft_directory that can be launched.

Request JSON Object:

  • craft_directory (string) – Name of the directory in the current saves “Ships” directory. For example "VAB" or "SPH".

Response JSON Object:

  • value (list<string>)

POST /space-center/launch-vessel#

Launch a vessel.

Note

The crew parameter controls how the craft is crewed:

  • If null, the craft’s default crew assignments are used.

  • If an empty list, the craft is launched with no crew.

  • Otherwise, the named Kerbals are placed in the craft in the order given: the first name takes the first seat, the second name the next seat, and so on, scanning the craft’s parts in order. No other Kerbals are hired to fill remaining seats. Throws an exception, without launching, if a name does not match an available Kerbal or the craft has too few seats for the requested crew.

Throws an exception if any of the games pre-flight checks fail.

Request JSON Object:

  • craft_directory (string) – Name of the directory in the current saves “Ships” directory, that contains the craft file. For example "VAB" or "SPH".

  • name (string) – Name of the vessel to launch. This is the name of the “.craft” file in the save directory, without the “.craft” file extension.

  • launch_site (string) – Name of the launch site. For example "LaunchPad" or "Runway".

  • crew (list<string>?) – The Kerbals to place in the craft, by name. Controls how the craft is crewed, as described in the remarks. Optional, defaults to null.

  • recover (bool) – If true and there is a vessel on the launch site, recover it before launching. Optional, defaults to true.

  • flag_url (string) – If not null, the asset URL of the mission flag to use for the launch. Optional, defaults to "".

POST /space-center/launch-vessel-from-vab#

Launch a new vessel from the VAB onto the launchpad.

Note

This is equivalent to calling POST /space-center/launch-vessel with the craft directory set to “VAB” and the launch site set to “LaunchPad”. Throws an exception if any of the games pre-flight checks fail.

Request JSON Object:

  • name (string) – Name of the vessel to launch.

  • recover (bool) – If true and there is a vessel on the launch pad, recover it before launching. Optional, defaults to true.

POST /space-center/launch-vessel-from-sph#

Launch a new vessel from the SPH onto the runway.

Note

This is equivalent to calling POST /space-center/launch-vessel with the craft directory set to “SPH” and the launch site set to “Runway”. Throws an exception if any of the games pre-flight checks fail.

Request JSON Object:

  • name (string) – Name of the vessel to launch.

  • recover (bool) – If true and there is a vessel on the runway, recover it before launching. Optional, defaults to true.

GET /space-center/editor#

The editor, for inspecting the vessel that is being constructed.

Response JSON Object:

  • value (SpaceCenter.Editor)

POST /space-center/save#

Save the game with a given name. This will create a save file called name.sfs in the folder of the current save game.

Request JSON Object:

  • name (string) – Name of the save.

POST /space-center/load#

Load the game with the given name. This will create a load a save file called name.sfs from the folder of the current save game.

Request JSON Object:

  • name (string) – Name of the save.

POST /space-center/quicksave#

Save a quicksave.

Note

This is the same as calling POST /space-center/save with the name “quicksave”.

POST /space-center/quickload#

Load a quicksave.

Note

This is the same as calling POST /space-center/load with the name “quicksave”.

GET /space-center/can-save#

Whether the game can be saved.

Note

The game cannot be saved in some flight states, e.g. while under acceleration or moving over the surface. Setting GET /krpc/game-scene to leave flight saves the game only when this is true.

Response JSON Object:

  • value (bool)

POST /space-center/can-revert-to-launch#

Whether the current flight can be reverted to launch.

Response JSON Object:

  • value (bool)

POST /space-center/revert-to-launch#

Revert the current flight to launch.

POST /space-center/transfer-crew#

Transfers a crew member to a different part.

Request JSON Object:

  • crew_member (SpaceCenter.CrewMember) – The crew member to transfer.

  • target_part (SpaceCenter.Part) – The part to move them to.

GET /space-center/ui-visible#

Whether the UI is visible.

Response JSON Object:

  • value (bool)

PUT /space-center/ui-visible#

Whether the UI is visible.

Request JSON Object:

  • value (bool) – The new value.

GET /space-center/navball#

Whether the navball is visible.

Response JSON Object:

  • value (bool)

PUT /space-center/navball#

Whether the navball is visible.

Request JSON Object:

  • value (bool) – The new value.

GET /space-center/altimeter-mode#

The current mode of the altimeter.

Response JSON Object:

  • value (SpaceCenter.AltimeterMode)

PUT /space-center/altimeter-mode#

The current mode of the altimeter.

Request JSON Object:

  • value (SpaceCenter.AltimeterMode) – The new value.

GET /space-center/ut#

POST /space-center/warp-to#

Uses time acceleration to warp forward to a time in the future, specified by universal time ut. This call blocks until the desired time is reached. Uses regular “on-rails” or physical time warp as appropriate. For example, physical time warp is used when the active vessel is traveling through an atmosphere. When using regular “on-rails” time warp, the warp rate is limited by max_rails_rate, and when using physical time warp, the warp rate is limited by max_physics_rate.

Note

Outside the flight scene, only regular “on-rails” time warp is used. Throws an exception if the game scene changes during the time warp.

Request JSON Object:

  • ut (double) – The universal time to warp to, in seconds.

  • max_rails_rate (float) – The maximum warp rate in regular “on-rails” time warp. Optional, defaults to 1e+05.

  • max_physics_rate (float) – The maximum warp rate in physical time warp. Optional, defaults to 2.0.
