Docking#

This tutorial docks two vessels in orbit. The script flies one vessel’s docking port into the port of another, and draws its approach in the game. It covers the following topics:

  • Measuring positions and velocities in a docking port’s reference frame

  • Pointing the vessel with the autopilot

  • Moving the vessel with its RCS thrusters

  • Drawing lines in the game with the Drawing service

You need two vessels in orbit a few tens of meters apart, each with a docking port. The vessel you fly also needs RCS thrusters and monopropellant. Before you run the script, right-click your vessel’s docking port and choose Control from here. Then right-click the other vessel’s docking port and choose Set as target.

The tutorial includes source code for the main client languages kRPC supports. Download the whole program in your chosen language:

Python, C#, C++, C, Java, Lua, JavaScript

Finding the Ports#

First we connect to the server and find the two docking ports. Our port is the part the vessel is controlled from, and the target port is the one you set as the target. The C program also defines sleep_ms, which its loop pauses with:

The script measures everything in the target port’s reference frame. Its origin is at the target port, and its y-axis points out of the port, along the path our port must take to dock. See the Reference Frames guide for more.

Approaching the Target#

Now we fly our port along the axis to the target port. Each pass of the loop picks a velocity to fly at, and fires the RCS thrusters to reach it. The loop ends when the magnets of the two ports catch each other, and our port’s state changes to docking:

    vessel.control.forward = max(-1, min(1, forward))

The script picks a goal on the axis to fly towards. While our port is more than 0.5 m off the axis, the goal is level with it, at least 5 m out from the target. So the vessel first moves sideways onto the axis. Once it is on the axis, the goal is the target port itself.

The speed towards the goal is a fifth of the distance to it, from 0.1 m/s to 1 m/s. So the vessel slows down as it closes in, and touches the target port gently.

The thrust is the difference between that velocity and the vessel’s velocity, doubled. The RCS controls take a direction in the vessel’s reference frame: right along its x-axis, forward along its y-axis, and up opposite its z-axis. So SpaceCenter.transform_direction() converts the thrust from the target port’s frame to the vessel’s frame.

The Python, C#, C++, Java and JavaScript scripts read the position and velocity from streams. The C and Lua clients do not support streams, so their scripts call for them on every pass.
