Threading#

This page covers using one connection from several threads, holding the condition of a stream, and the threads callbacks run on.

Calls#

threading-calls-on-several-threads [threads] [MUST]

Calls made from several threads on one connection each return their own result.

threading-interleaved-calls [threads] [MUST]

A call on one thread writes its request while a call on another thread waits for its response. Each call returns its own result, in whichever order the responses arrive.

threading-streams-added-on-several-threads [streams, threads] [MUST]

Streams added from several threads at once are each registered.

threading-close-with-a-call-in-flight [threads] [MUST]

A thread closes the connection while another thread waits for a response. The waiting call raises the connection error.

threading-response-after-close [threads] [MUST]

A response that arrives after the client sends its disconnect does not reach the call waiting for it. The call raises the connection error.

Conditions#

Each stream has a condition: a lock that a thread holds while it reads the stream’s value and waits for the next one. While a thread holds it, the value the thread reads changes only when it waits, so the thread misses no update. The connection has a condition for its updates too.

threading-wait-holding [streams, conditions] [MUST]

A thread holding a stream’s condition sees one update per wait, and the value after the wait is the next value. While it holds the condition, a zero timeout returns false.

threading-wait-for-update [streams, conditions] [SHOULD]

The client offers a wait for the next update message of any stream, under a condition for the connection’s updates. Holding that condition, a thread sees one update per wait.

threading-held-value [streams, conditions, threads] [MUST]

While a thread holds the condition of a stream, the value it reads changes only when it waits. A thread that does not hold the condition reads the latest value. A wait returns for a value that arrived while the holder read the old one.

threading-held-stream-ending [streams, conditions, threads] [MUST]

While a thread holds the condition of a stream, an error that ends the stream reaches it as a value does. The thread reads the old value until it waits. The wait returns, and later reads and waits raise the error.

threading-held-stream-ending-before-value [streams, conditions, threads] [MUST]

While a thread holds the condition of a stream with no value, an error ends the stream. A read on the thread raises the error.

threading-wait-for-unread-value [streams, conditions] [MUST]

A wait returns only for a value newer than the last one the thread read, including a value it read without holding the condition.

threading-value-read-before-wake [streams, conditions, races] [MUST]

A wait does not return for a value the thread read before the update woke the stream’s waiters.

threading-call-while-holding [streams, conditions] [MUST]

A thread holding the condition of a stream makes a call, which returns.

threading-wait-on-condition-object [streams, conditions, threads] [MUST]

A thread holding a stream’s condition waits on the condition object itself, as the language waits on a condition variable. Other threads can take the condition while it waits. An update wakes the wait, and the thread then holds the condition again.

threading-spurious-wake [streams, events, conditions, threads] [MUST]

A wait with a timeout, woken by a notification of the condition with no update, waits on until the timeout and returns false.

Sharing a Condition#

threading-hold-twice [streams, conditions, threads] [MUST]

A thread holding the condition of a stream takes it again. Other threads wait for the condition until the thread releases every hold.

threading-wait-holding-twice [streams, conditions, threads] [MUST]

A thread that holds the condition of a stream twice waits on it. The wait returns for an update, or times out, and the thread then holds the condition twice again.

threading-copies-share-condition [streams, conditions, threads] [MUST]

Copies of a stream handle share one condition. A thread holds it through each copy at once, and other threads wait for it until the thread releases both holds.

threading-event-shares-condition [events, conditions, threads] [MUST]

An event and its stream share one condition. A thread holding it through the event keeps other threads from taking it through the stream.

threading-release-through-another-handle [events, conditions, threads] [MUST]

A thread lets go of a condition through a handle other than the one it took the condition through, which shares the condition: the event’s stream for an event, the event for its stream, or a copy of a stream handle. Other threads can then take the condition.

Removing and Closing#

threading-remove-while-holding [streams, conditions] [MUST]

A thread holding the condition of a stream removes the stream, while updates for the stream arrive. A wait by that thread then raises the error for a removed stream.

threading-remove-event-while-holding [events, conditions] [MUST]

A thread holding the condition of an event removes the event, while the event fires. A wait by that thread then raises the error for a removed stream, at once.

threading-close-while-holding [streams, conditions] [MUST]

A thread holding the condition of a stream, or the condition for the connection’s updates, closes the connection while updates for the stream arrive. A wait on the stream by that thread then raises the connection error, and the stream’s end callbacks are called once.

threading-wait-holding-another [streams, conditions, threads] [MUST]

A thread holding the condition of one stream waits on a second stream. The wait returns on the second stream’s next update, when an update of the first stream arrives before it.

threading-wake-waiter-holding-another [streams, conditions, threads] [MUST]

A close or a failure of the connection wakes two threads: one waiting on a stream while it holds the condition of a second stream, and one waiting on that second stream. Both waits raise the connection error. The wait on the second stream raises once the first thread lets go of its condition.

threading-wake-update-waiter [streams, conditions, threads] [MUST]

A close or a failure of the connection wakes a thread waiting for an update while it holds the condition of a stream. The wait returns or raises the connection error, and a read of the stream then raises the connection error.

threading-interrupted-wait [streams, events, threads] [MUST]

Interrupting a thread that waits on a stream or an event, such as with Thread.interrupt in Java, ends the wait with an error. The stream or event runs on.

Callbacks and Conditions#

threading-remove-callback-while-holding [streams, callbacks, conditions] [MUST]

A thread holding the condition of a stream removes a callback of the stream, while updates for the stream arrive. The remove returns, and a later wait returns for the next update.

threading-close-while-callback-waits [streams, callbacks, conditions] [MUST]

A thread holding the condition of a stream closes the connection, while a callback of another stream waits to take that condition. The stream held can be one the client removed. The close returns, and the connection is closed.

threading-add-callback-while-callback-waits [streams, callbacks, conditions] [MUST]

A thread holding the condition of a stream adds a callback to another stream, while a callback of that stream waits to take the condition. The add returns.

Callback Threads#

threading-callbacks-run-off-the-caller [streams, callbacks, threads] [MUST]

Callbacks for stream updates run on a thread of the client, and never on a thread that makes calls. The first call of a callback, with the value the stream already has, may run on the thread that adds it.

threading-first-call-waits [streams, callbacks] [MUST]

The first call of a callback can wait for a later update of its stream. The wait returns, whether the call runs on the thread that adds the callback or on a thread of the client.

threading-blocked-callback [streams, callbacks, threads] [MUST]

Calls return, and reads of a stream return its latest value, while a callback blocks. Waits and other callbacks can stall. The callback is passed the latest value once it returns.

threading-callback-one-thread-at-a-time [streams, callbacks] [MUST]

A callback never runs on two threads at once.

threading-close-during-first-call [streams, callbacks, threads, races] [MUST]

Closing the connection returns while an update of a stream waits for the first call of a callback to finish.

threading-update-callback-after-close [streams, callbacks, threads, races] [MUST]

An update callback is not called once the connection is closed, though the update arrived before the close.

Calls From Callbacks#

threading-call-from-a-callback [streams, callbacks] [MUST]

A callback makes a call, which returns its result.

threading-remove-stream-from-callback [streams, callbacks] [MUST]

A callback removes the stream it is called for. The remove returns, and a read of the stream then raises the error for a removed stream.

threading-remove-callback-from-itself [streams, callbacks] [MUST]

A callback removes itself, and is not called again.

threading-close-from-a-callback [streams, callbacks] [MUST]

A callback closes the connection, from its first call or a later one. The end callbacks of the stream are called.

threading-close-from-an-end-callback [streams, callbacks] [MUST]

An end callback closes the connection, whether the stream was removed or ended with an error. The end callbacks of the other streams are called.
