Server Side Functions#

This page covers streaming and running server side functions, which are described under Server Side Functions.

Streams#

functions-stream [functions, streams] [MUST]

A stream of a function delivers the function’s value as it changes.

functions-stream-error [functions, streams] [MUST]

An error from a function ends its stream with that error, and leaves other streams running.

functions-two-streams-of-one-function [functions, streams] [MUST]

Each stream added for one function is a separate stream. Removing one leaves the other, and reading the removed one raises the error for a removed stream.

Events#

functions-add-event [events, functions] [MUST]

An event added with KRPC.AddEvent, over a server side function, fires.

functions-two-events-of-one-function [events, functions] [MUST]

Each event added for one function is a separate event. Removing one leaves the other.

Running#

functions-run [functions] [MUST]

Running a function passes the arguments to its parameters in order, and returns its value.

functions-argument-types [functions] [MUST]

A run passes an argument of each type to its parameter, and decodes a value of each type. NaN, the infinities, the extremes of each integer type and a null arrive intact.

functions-run-a-call [functions] [MUST]

The client builds a function that makes a call with KRPC.Expression.Call, from the same call it builds for a stream of the procedure. Running the function returns the call’s result.

functions-run-error [functions] [MUST]

An error from a function raises that error from the run.

functions-run-argument-errors [functions] [MUST]

A wrong number of arguments, an argument of the wrong type, a number out of the range of the parameter’s type, or a null for a parameter that cannot hold null, raises the argument error. This includes a collection whose items do not match the parameter’s type. The error can be the server’s KRPC.ArgumentException, for a client that maps it to its argument error.

functions-stream-with-parameters [functions, streams] [MUST]

Adding a stream for a function with parameters raises the client’s argument error.

functions-event-with-parameters [events, functions] [MUST]

Adding an event for a function with parameters raises the client’s argument error.

Values#

functions-value-types [functions] [MUST]

A run decodes the function’s value at its type. This holds for a floating point number, a null, a list, an empty list, a list holding a null, an object, a structure, and a list, a dictionary and a tuple that each hold a null object.

functions-stream-value-types [functions, streams] [MUST]

A stream decodes the function’s value at its type, for each type a run decodes.

functions-mismatched-type [functions, function-types] [MUST]

A run at a type that does not describe the function’s value raises the argument error. This holds for a tuple of another length, a set read as a list, a dictionary of another value type, an enumeration read as an integer, and a list that can hold null read as one that cannot.

functions-stream-mismatched-type [functions, function-types, streams] [MUST]

Adding a stream at a type that does not describe the function’s value raises the argument error, for each mismatch a run rejects.

functions-null-for-non-nullable-type [functions] [MUST]

A function whose value is null, run at a type that cannot hold null, raises the encoding error. This holds for a double and for an object.

functions-stream-null-for-non-nullable-type [functions, streams] [MUST]

Reading a stream of a function whose value is null, at a type that cannot hold null, raises the encoding error. This holds for a double and for an object.

functions-null-in-callback [callbacks, functions, streams] [MUST]

A callback on a stream of a function, at a type that cannot hold null, is not called for a null value. It is called for the values that follow. This holds for a double and for an object.
