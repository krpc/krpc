Server Side Functions#

A server side function is code that runs inside the game, on the server. It has three main uses:

  • Custom events wait for a condition to become true. The server checks the condition every physics tick, and sends your program a message when it fires. Polling from your program adds a round trip to every check, and can miss a condition that holds for only a few ticks.

  • Function streams stream the result of a computation over several RPC values. The server reads every value in the same physics tick, so the values are consistent. It sends the result to your program when the result changes.

  • Run-once functions run a sequence of calls and computation in a single physics tick, from a single RPC. They can set properties and trigger actions. The same calls made from your program take a round trip each, and the game advances between them.

This guide is in two parts. Using Server Side Functions covers functions written in your own language and compiled by the client, and is all most users need. The Expression API covers the expression trees that compiled code translates into, which every client can build directly.

Note

Compiled functions need the Python or C# client. Events, function streams and Run need the Python, C#, C++ or Java client.

Using Server Side Functions#

A client with a compiler turns a function or lambda into a server side function. It is the simplest way to write one. The constructs a compiler supports depend on the language. A language whose lambdas hold a single expression builds statements and exception handlers with the expression API.

A First Custom Event#

This event fires when the vessel’s altitude exceeds 1000 meters:

event = conn.add_event(lambda: flight.mean_altitude > 1000)
with event.condition:
    event.wait()
    print("Altitude reached 1000m")

var evnt = connection.AddEvent (() => flight.MeanAltitude > 1000);
lock (evnt.Condition) {
    evnt.Wait ();
    Console.WriteLine ("Altitude reached 1000m");
}

The client compiles the lambda into a server side function. The mean altitude call becomes an embedded RPC, re-invoked on each check. 1000 becomes a constant.

Remote Calls and Captured Values#

The compiler splits a function by what each part depends on:

  • Reading a property or calling a method of a remote object or service becomes part of the function. The server re-invokes it on every evaluation. So does any operation on its result, such as arithmetic or a square root.

  • A sub-expression that uses only client side values, such as captured variables and literals, is evaluated once, when the function is compiled. That includes arithmetic and library calls on those values. The result becomes a constant.

For example:

threshold = 50000
event = conn.add_event(lambda: vessel.orbit.apoapsis_altitude > threshold * 2)

var threshold = 50000;
var evnt = connection.AddEvent (
    () => vessel.Orbit.ApoapsisAltitude > threshold * 2);

The client computes threshold * 2 when it creates the event, so the function compares the apoapsis with the constant 100000. To use a new value of threshold, compile a new function and remove the old event.

A chain of calls is embedded whole. Both the orbit and the apoapsis altitude calls are part of the function, so it follows the vessel’s current orbit each tick.

Computed Streams#

Pass a function when creating a stream to stream its computed value. The server runs the computation on each stream update:

# The vessel's altitude, in kilometers, computed on the server
stream = conn.add_stream(lambda: flight.mean_altitude / 1000)
print("Altitude:", stream(), "km")

// The vessel's altitude, in kilometers, computed on the server
var stream = connection.AddStream (() => flight.MeanAltitude / 1000);
Console.WriteLine ("Altitude: " + stream.Get () + " km");

A function can produce a collection. This streams the thrust of every engine on the vessel, read in a single physics tick per update:

engines = vessel.parts.engines
stream = conn.add_stream(lambda: [engine.thrust for engine in engines])
for thrust in stream():
    print(thrust)

var engines = vessel.Parts.Engines;
var stream = connection.AddStream (
    () => engines.Select (engine => engine.Thrust).ToList ());
foreach (var thrust in stream.Get ())
    Console.WriteLine (thrust);

Here engines is a captured variable, so the list of engines is fixed when the function is compiled. The server re-reads only their thrusts. Read the engine list inside the function to have the server fetch the list on each update. That follows staging, at the cost of extra work per update.

Collections#

The language’s collection operations, such as mapping, filtering, counting, summing and sorting, compile to the server’s collection operations. This event fires when any engine on the vessel runs out of fuel. The server re-reads the engine list on each check, so the event covers engines that staging reveals:

event = conn.add_event(
    lambda: any(not engine.has_fuel for engine in vessel.parts.engines)
)
with event.condition:
    event.wait()
    print("An engine has run out of fuel")

var evnt = connection.AddEvent (
    () => vessel.Parts.Engines.Any (engine => !engine.HasFuel));
lock (evnt.Condition) {
    evnt.Wait ();
    Console.WriteLine ("An engine has run out of fuel");
}

Statements, Loops and Local Variables#

A compiled function can contain statements before its return. This computes the fraction of liquid fuel left:

def fuel_fraction():
    resources = vessel.resources
    amount = resources.amount("LiquidFuel")
    capacity = resources.max("LiquidFuel")
    return amount / capacity


stream = conn.add_stream(fuel_fraction)

// A C# lambda holds a single expression
var stream = connection.AddStream (
    () => vessel.Resources.Amount ("LiquidFuel") / vessel.Resources.Max ("LiquidFuel"));

A compiled function supports these statements:

  • If statements, with else branches.

  • While and for-each loops, with break and continue.

  • Early returns.

  • Local variables, which can be reassigned and changed in place. A loop can build up a collection in one.

A collection a call returns is a copy, as it is in your program. Changing the copy in a function leaves the game’s own collection unchanged.

A variable takes its type from its first assignment. Give an empty collection its element type with a type annotation:

def burn_ratings():
    ratings: list[str] = []
    for engine in vessel.parts.engines:
        if not engine.active:
            continue
        if engine.thrust > 0.9 * engine.available_thrust:
            ratings.append("full")
        else:
            ratings.append("partial")
    return ratings


print(conn.run(burn_ratings))

// A C# lambda holds a single expression, so LINQ operators replace the loop
var ratings = connection.Run (
    () => vessel.Parts.Engines
        .Where (engine => engine.Active)
        .Select (engine =>
            engine.Thrust > 0.9 * engine.AvailableThrust ? "full" : "partial")
        .ToList ());
Console.WriteLine (string.Join (", ", ratings));

A counter that starts as an integer and later holds a fraction takes an annotation too, such as total: float = 0.

Side Effects and Run-Once Functions#

A compiled function can also change the game. It can assign to the properties of remote objects and services, and call methods for their effects. Pass such a function to Run, which evaluates it once, with every step in the same physics tick:

def deploy():
    for parachute in vessel.parts.parachutes:
        if not parachute.deployed:
            parachute.deploy()


conn.run(deploy)

// A single side-effecting call, run on the server
connection.Run (() => vessel.Control.ToggleActionGroup (1));

// Compute and return a value in one tick
var altitude = connection.Run (() => flight.MeanAltitude / 1000);

The game holds still between the steps, and the whole function costs one round trip. A function that returns no value gives the client’s null value, or runs through a void overload where the client has one.

Note

An event or stream re-runs its function on every stream update, effects included. Keep event and stream functions free of side effects.

Function Arguments#

A compiled function can take parameters, and Run passes it a value for each. One function then serves many inputs. This computes how long a burn takes, for several changes in velocity:

@conn.compile
def burn_time(delta_v: float) -> float:
    exhaust_velocity = vessel.specific_impulse * 9.82
    final_mass = vessel.mass / math.exp(delta_v / exhaust_velocity)
    return (vessel.mass - final_mass) * exhaust_velocity / vessel.available_thrust


for delta_v in (100.0, 250.0, 400.0):
    print(conn.run(burn_time, delta_v))

var burnTime = connection.Compile ((double deltaV) =>
    (vessel.Mass - vessel.Mass / Math.Exp (deltaV / (vessel.SpecificImpulse * 9.82)))
        * vessel.SpecificImpulse * 9.82 / vessel.AvailableThrust);
foreach (var deltaV in new [] { 100.0, 250.0, 400.0 })
    Console.WriteLine (connection.Run<double> (burnTime, deltaV));

In Python, the function is a def with a type annotation on each parameter. Its arguments bind as Python binds them, with defaults and keyword arguments. In C#, the function is a lambda with typed parameters. An event or a stream runs its function with no arguments.

State Between Updates#

A function can keep a value from one evaluation to the next, such as a running total. In Python, declare a captured variable nonlocal. This stream counts the stream updates in which the engines are firing:

def firing_counter():
    updates = 0

    @conn.compile
    def count():
        nonlocal updates
        if vessel.thrust > 0:
            updates += 1
        return updates

    return count


stream = conn.add_stream(firing_counter())

The variable starts with the value it holds when the function is compiled, and takes its type from that value. To give it another type, such as a list that starts empty, start the function with a cast of it: history = cast(List[float], history).

The server keeps the value apart from the variable on the client. A compiled function keeps its state across every run, stream and event. The state belongs to the function, so two streams of one compiled function advance it twice per update. Compile the function twice for separate states.

A function passed straight to Run or a stream starts again from the captured value on each call. With the expression API, create the variable with Expression.state_variable().

Strings#

A string has its own operations, separate from the collection operations. The compilers choose them from the type of the value. This streams the vessel’s name in upper case:

stream = conn.add_stream(lambda: vessel.name.upper())

var stream = connection.AddStream (() => vessel.Name.ToUpperInvariant ());

The compilers translate the language’s string operations, such as length, indexing, searching, splitting and case conversion. The expression API names them Expression.string_length(), Expression.string_get(), Expression.string_substring() and so on. Passing a string to a collection operation is an error that points at them.

Two rules apply to strings:

  • A character is a string of length one. The protocol carries no character type, so indexing a string produces a one character string, which works with every other string operation. In a language where indexing a string produces a character, that index is an unsupported construct. Take a substring in its place.

  • Case conversion and comparison are the same in every locale. Case is converted, and strings are compared, by ordinal value. A function produces the same result whatever language the game runs in.

Exceptions#

A function can raise an exception. It reaches your program as an error from Run, or as an error on the stream or event evaluating the function:

def check_fuel():
    if vessel.resources.amount("LiquidFuel") < 100:
        raise RuntimeError("not enough fuel")

// A C# lambda cannot throw, so the expression API builds the statement
// around a compiled condition
var checkFuel = Expression.IfThen (connection,
    connection.Compile (() => vessel.Resources.Amount ("LiquidFuel") < 100),
    Expression.Throw (connection, "KRPC", "InvalidOperationException",
        Expression.ConstantString (connection, "not enough fuel")));

A function raises the exceptions services declare, so your program catches a typed exception. A service’s own exception classes map onto themselves.

A compiler maps the language’s built-in exceptions onto the general kRPC exceptions, for example an invalid operation to InvalidOperationException and a bad index to IndexOutOfRangeException. The language’s base exception class raises a KRPC.Error, for a condition no other exception describes.

A function can also handle an exception, with the language’s try statement:

def switch_modes() -> str:
    try:
        for engine in vessel.parts.engines:
            engine.toggle_mode()
        return "switched"
    except Exception as error:
        return "could not switch: " + error

// A C# lambda cannot hold a loop or a handler, so the expression API builds them
var engine = Expression.Variable (connection, "engine",
    Type.ClassType (connection, "SpaceCenter", "Engine"));
var result = Expression.Variable (connection, "result", Type.String (connection));
var error = Expression.Variable (connection, "error", Type.String (connection));
var toggleMode = Connection.GetCall (
    (System.Linq.Expressions.Expression<Action>)
    (() => vessel.Parts.Engines [0].ToggleMode ()));
var switchModes = Expression.BlockWithVariables (connection,
    new List<Expression> { engine, result, error },
    new List<Expression> {
        Expression.TryCatchAll (connection,
            Expression.Block (connection, new List<Expression> {
                Expression.ForEach (connection, engine,
                    connection.Compile (() => vessel.Parts.Engines),
                    Expression.CallWithArguments (connection, toggleMode,
                        new Dictionary<int, Expression> { { 0, engine } })),
                Expression.Assign (connection, result,
                    Expression.ConstantString (connection, "switched"))
            }),
            error,
            Expression.Assign (connection, result,
                Expression.StringConcat (connection, new List<Expression> {
                    Expression.ConstantString (connection, "could not switch: "),
                    error
                }))),
        result
    });

These rules apply to handlers:

  • Only the message of an exception is exposed. The variable a handler binds is a string holding the message.

  • Naming an exception catches every form of it. A service raises a .NET exception, which the server reports under its kRPC name. A handler for a kRPC exception catches the exceptions procedures raise, as well as the ones the function raises.

  • A procedure that pauses execution passes through every handler, including a catch-all. It is reported as an error.

  • Two failures of an embedded call have no exception type, so only a catch-all handles them. Both reach your program as errors without a name:

    • A call to a procedure that is unavailable in the current game scene.

    • A procedure that returns null although its return type is not nullable.

The Standard Library#

The StdLib service provides mathematics for server side functions. Calls to the language’s math library compile to the matching StdLib procedures when their arguments are computed on the server. Call the service directly for the vector and quaternion operations. This streams the angle between the vessel’s facing direction and its velocity relative to the surface:

stdlib = conn.std_lib
frame = vessel.orbit.body.reference_frame
stream = conn.add_stream(
    lambda: stdlib.radians_to_degrees(
        stdlib.vector_angle(vessel.direction(frame), vessel.velocity(frame))
    )
)

var stdlib = connection.StdLib ();
var frame = vessel.Orbit.Body.ReferenceFrame;
var stream = connection.AddStream (
    () => stdlib.RadiansToDegrees (stdlib.VectorAngle (
        vessel.Direction (frame), vessel.Velocity (frame))));

The service covers:

  • Scalar functions, such as square roots, trigonometry and clamping, and the constants pi and e.

  • Vector operations on the position and direction tuples of the SpaceCenter service, such as dot and cross products, magnitudes, angles and interpolation.

  • Quaternion operations on its rotation tuples, such as composition, inverses, rotating vectors and interpolation.

Angles are in radians, with converters to and from degrees. StdLib.log() takes the base of the logarithm, and is natural without one.

Each midpoint rounding rule has its own procedure, so a function can round the way its language does:

  • StdLib.round() rounds a halfway value to the nearer even number, as Python and C# do.

  • StdLib.round_half_away_from_zero() rounds it away from zero, as C and C++ do.

  • StdLib.round_half_up() rounds it toward positive infinity, as Java does.

Each takes the number of decimal places, negative for tens and hundreds. A compiled rounding call uses the procedure for its rounding rule.

Printing#

The language’s print function compiles to StdLib.print(), which writes a line to the game’s log, KSP.log. This logs the vessel’s mass from the server:

conn.run(lambda: print("Mass:", vessel.mass, "kg"))

connection.Run (
    () => Console.WriteLine (FormattableString.Invariant ($"Mass: {vessel.Mass} kg")));

A print in an event or stream function writes a line on every stream update.

Supported Constructs#

The compilers support each construct with a server side equivalent: arithmetic, comparisons, boolean operators, conditional expressions, collection constructors, indexing, membership tests, and the collection and string operations. Where the language allows them, the compilers also support statements, changing a collection in place, and raising and handling exceptions.

Any other construct raises a compilation error that names it. Examples are a format specifier, and a call to a client side function with server side arguments.

A few semantics differ from running the same code in your program:

  • A sub-expression that uses only client side values is evaluated once, when the function is compiled. A remote call made inside a client side function would run only once.

  • In Python, a call to a client side function must give the same answer whenever it runs. A client side function that makes a remote call is an error.

  • In C#, a call that can run code outside the .NET base library, the kRPC client and the service stubs is an error. Examples are a delegate call, and a method, constructor, computed property or operator defined in your program.

  • A client side call written as a statement, such as a sleep, is an error.

  • A rounding mode must be a constant, as it selects the server side procedure.

  • The language’s own rules for the code a compiler accepts still apply.

Each client guide lists the constructs its compiler supports, and the rules of its language: C# and Python.

Errors, Edge Cases and Performance#

Errors. An error raised while evaluating a stream or event function reaches your program when it reads the stream or event. An example is an embedded call reaching a destroyed part.

The server then removes the stream, as it does for any stream whose result is an error. Build a new event or stream once the cause clears.

Loads and unloaded vessels. A function that reads an object the game has not loaded raises KRPC.ObjectNotLoadedException. Examples are a part of an unloaded vessel, and a vessel part way through a load. The exception ends a function stream or event like any other. To keep one running, catch the exception in the function:

import krpc

conn = krpc.connect()
vessel = conn.space_center.active_vessel
flight = vessel.flight()


def above_1000m() -> bool:
    try:
        return flight.mean_altitude > 1000
    except conn.krpc.ObjectNotLoadedException:
        return False


event = conn.add_event(above_1000m)
with event.condition:
    event.wait()
    print("Altitude reached 1000m")

using System;
using System.Collections.Generic;
using KRPC.Client;
using KRPC.Client.Services.KRPC;
using KRPC.Client.Services.SpaceCenter;
using Type = KRPC.Client.Services.KRPC.Type;

class Program {
    public static void Main() {
        var connection = new Connection();
        var spaceCenter = connection.SpaceCenter();
        var flight = spaceCenter.ActiveVessel.Flight();

        // A C# lambda cannot hold a handler, so the expression API builds it
        // around a compiled condition
        var above = Expression.Variable(connection, "above", Type.Bool(connection));
        var above1000m = Expression.BlockWithVariables(connection,
            new List<Expression> { above },
            new List<Expression> {
                Expression.TryCatch(connection,
                    Expression.Assign(connection, above,
                        connection.Compile(() => flight.MeanAltitude > 1000)),
                    "KRPC", "ObjectNotLoadedException", null,
                    Expression.Assign(connection, above,
                        Expression.ConstantBool(connection, false))),
                above
            });

        var evnt = connection.AddEvent(above1000m);
        lock (evnt.Condition) {
            evnt.Wait();
            Console.WriteLine("Altitude reached 1000m");
        }
    }
}

#include <iostream>
#include <optional>
#include <vector>
#include <krpc.hpp>
#include <krpc/function_stream.hpp>
#include <krpc/services/krpc.hpp>
#include <krpc/services/space_center.hpp>

int main() {
  auto conn = krpc::connect();
  krpc::services::SpaceCenter sc(&conn);
  auto flight = sc.active_vessel().value().flight();

  typedef krpc::services::KRPC::Expression Expr;
  typedef krpc::services::KRPC::Type KType;

  // above = mean_altitude > 1000, or false if the vessel is not loaded
  auto above = Expr::variable(conn, "above", KType::bool_(conn));
  auto above_1000m = Expr::block_with_variables(
    conn,
    std::vector<Expr>({above}),
    std::vector<Expr>({
      Expr::try_catch(conn,
        Expr::assign(conn, above,
          Expr::greater_than(conn,
            Expr::call(conn, flight.mean_altitude_call()),
            Expr::constant_double(conn, 1000))),
        "KRPC", "ObjectNotLoadedException", std::nullopt,
        Expr::assign(conn, above, Expr::constant_bool(conn, false))),
      above}));

  auto event = krpc::add_event(above_1000m);
  event.acquire();
  event.wait();
  std::cout << "Altitude reached 1000m" << std::endl;
  event.release();
}

import krpc.client.Connection;
import krpc.client.Event;
import krpc.client.RPCException;
import krpc.client.StreamException;
import krpc.client.services.KRPC.Expression;
import krpc.client.services.KRPC.Type;
import krpc.client.services.SpaceCenter;
import krpc.client.services.SpaceCenter.Flight;

import java.io.IOException;
import java.util.Arrays;

public class NotLoadedEvent {
  public static void main(String[] args) throws IOException, RPCException, StreamException {
    try (Connection connection = Connection.newInstance()) {
      SpaceCenter spaceCenter = SpaceCenter.newInstance(connection);
      Flight flight = spaceCenter.getActiveVessel().flight(null);

      // above = meanAltitude > 1000, or false if the vessel is not loaded
      Expression above = Expression.variable(connection, "above", Type.bool(connection));
      Expression above1000m = Expression.blockWithVariables(
        connection,
        Arrays.asList(above),
        Arrays.asList(
          Expression.tryCatch(connection,
            Expression.assign(connection, above,
              Expression.greaterThan(connection,
                Expression.call(connection, connection.getCall(flight, "getMeanAltitude")),
                Expression.constantDouble(connection, 1000))),
            "KRPC", "ObjectNotLoadedException", null,
            Expression.assign(connection, above,
              Expression.constantBool(connection, false))),
          above));

      Event event = connection.addEvent(above1000m);
      synchronized (event.getCondition()) {
        event.waitFor();
        System.out.println("Altitude reached 1000m");
      }
    }
  }
}

The event’s handler gives False, so the event does not fire. A stream’s handler can give a last good value, kept in a state variable. With the expression API, Expression.try_catch() names the exception as "KRPC", "ObjectNotLoadedException".

Procedures that pause. Some procedures pause execution and resume on a later tick, such as SpaceCenter.WarpTo and SpaceCenter.LaunchVessel. Calling one is an error in any function. The procedure keeps its effects up to the pause, so a WarpTo called this way leaves the game warping.

Loops run to completion. A while loop runs to its end within a single tick, before the game continues. A loop that never ends hangs the game until the game is closed. Bound every loop by a value that is certain to change.

Null values. A procedure that can return null, such as Part.engine, gives a value to compare with null, or to test with Expression.is_null(). A value of any type can be nullable, and a function tracks which values are. A nullable number works in arithmetic like any other number.

A null reaching a position that cannot hold one raises a NullReferenceException when the function runs. These positions are the arguments, operands and variables whose types are not nullable. A client raises it as the closest built-in exception of its language.

A function can produce a null. A compiled null takes its type from where it is used, such as the other assignment to a variable or the other branch of a conditional:

def heaviest_engine():
    best = None
    for engine in vessel.parts.engines:
        if best is None or engine.part.mass > best.part.mass:
            best = engine
    return best

var heaviest = connection.Run (
    () => vessel.Parts.Engines.Count == 0 ? null
        : vessel.Parts.Engines.OrderBy (engine => engine.Part.Mass).Last ());

Elsewhere, give a null its type with a type annotation or a cast. The expression API has Expression.constant_null().

A function whose result is null gives your program the client’s null value. Decoding a null into a type that cannot hold one is an error.

A client that takes the result type as a type argument needs a type that can hold null. The same holds for the nulls inside a result, such as the objects in a list a procedure returns.

Costs. A function is evaluated on the server as native code, and only its result crosses the network. Even a large function evaluates quickly.

Reuse a function. A function stays on the server until the server stops. Passing a new lambda to Run in a loop builds and keeps a new function on each pass. Each pass reads the lambda’s captured variables again, while a compiled function keeps the values from when it was compiled.

Compile a function once, and run the compiled function as often as needed. To run it with different values, give it parameters, as in Function Arguments:

step = conn.compile(lambda: vessel.control.toggle_action_group(1))
while True:
    conn.run(step)

var step = connection.Compile (() => vessel.Control.ToggleActionGroup (1));
while (true)
    connection.Run (step);

Compiling a function also compiles it to native code on the server. A lambda passed straight to Run is compiled there on every call, on the game’s main thread, so a large one can make the game stutter.

Compile a function before it is needed, such as before launch, and every run is fast. For a function built with the expression API, KRPC.CompileFunction compiles it on the server.

The Expression API#

The expression API builds a server side function node by node. It is how the C++ and Java clients write functions, and how C# writes the statements a lambda cannot hold. The compilers produce the same functions.

Expression Trees#

A server side function is a tree of expression objects held on the server, built with the static methods of the Expression class. The server compiles the tree to native code, so evaluations are fast.

Each node is a constant, an embedded remote procedure call, an operator, a statement or a nested function. Statements are assignments, loops and if statements.

Three RPCs consume these trees:

  • AddEvent takes a function that evaluates to a boolean, and returns an event. The server evaluates the function on each stream update, and triggers the event when it returns true.

  • AddFunctionStream takes a function whose value can be sent to a client, such as a number, a string, a collection or an object. It returns a stream of the value, recomputed on each stream update.

  • RunFunction evaluates a function once, within a single physics tick, and returns its value. Use it for a function with side effects.

Two rules hold for every server side function:

  • Embedded remote procedure calls are re-invoked on every evaluation. Constants, and the values your program supplies when building the function, are fixed when the function is created.

  • The whole function is evaluated within a single physics tick. A function that reads the fuel level of every engine reads them all in the same tick. The same calls made from your program read them over several ticks, as the game advances.

Expression Objects#

The altitude event from the start of this guide has three nodes: an embedded call, a constant and a comparison:

import krpc

conn = krpc.connect()
vessel = conn.space_center.active_vessel
flight = vessel.flight()

# Convert a remote procedure call to a message,
# so it can be passed to the server
mean_altitude = conn.get_call(getattr, flight, "mean_altitude")

# Build the function on the server
expr = conn.krpc.Expression.greater_than(
    conn.krpc.Expression.call(mean_altitude), conn.krpc.Expression.constant_double(1000)
)

# Create an event from the function
event = conn.add_event(expr)

# Wait on the event
with event.condition:
    event.wait()
    print("Altitude reached 1000m")

using System;
using KRPC.Client;
using KRPC.Client.Services.KRPC;
using KRPC.Client.Services.SpaceCenter;

class Program {
    public static void Main() {
        var connection = new Connection();
        var spaceCenter = connection.SpaceCenter();
        var flight = spaceCenter.ActiveVessel.Flight();

        // Get the remote procedure call as a message object,
        // so it can be passed to the server
        var meanAltitude = Connection.GetCall(() => flight.MeanAltitude);

        // Build the function on the server
        var expr = Expression.GreaterThan(connection,
            Expression.Call(connection, meanAltitude),
            Expression.ConstantDouble(connection, 1000));

        var evnt = connection.AddEvent(expr);
        lock (evnt.Condition) {
            evnt.Wait();
            Console.WriteLine("Altitude reached 1000m");
        }
    }
}

import krpc.client.Connection;
import krpc.client.RPCException;
import krpc.client.Event;
import krpc.client.StreamException;
import krpc.client.services.KRPC.Expression;
import krpc.client.services.SpaceCenter;
import krpc.client.services.SpaceCenter.Flight;
import krpc.schema.KRPC.ProcedureCall;

import java.io.IOException;

public class CustomEvent {
  public static void main(String[] args) throws IOException, RPCException, StreamException {
    try (Connection connection = Connection.newInstance()) {
      SpaceCenter spaceCenter = SpaceCenter.newInstance(connection);
      Flight flight = spaceCenter.getActiveVessel().flight(null);

      // Get the remote procedure call as a message object,
      // so it can be passed to the server
      ProcedureCall meanAltitude = connection.getCall(flight, "getMeanAltitude");

      // Build the function on the server
      Expression expr = Expression.greaterThan(
        connection,
        Expression.call(connection, meanAltitude),
        Expression.constantDouble(connection, 1000));

      Event event = connection.addEvent(expr);
      synchronized (event.getCondition()) {
        event.waitFor();
        System.out.println("Altitude reached 1000m");
      }
    }
  }
}

Two kinds of object appear here:

  • A procedure call message describes an RPC without invoking it. Each client builds one from a call written in its own language, as the examples show. Building a call message is a local operation.

  • An expression object is a node of the tree. Expression.call() embeds a procedure call message, which the server invokes on each evaluation. A procedure with no return value embeds as a statement.

Each factory method is an RPC that creates one node on the server and returns a handle to it. Building a function costs one RPC per node, paid once.

Operators and Types#

This truncates the altitude to a whole number of meters:

# Truncate the altitude to a whole number of meters
expr = expression.cast(expression.call(mean_altitude), types.int())

// Truncate the altitude to a whole number of meters
var expr = Expression.Cast (connection,
    Expression.Call (connection, meanAltitude),
    Type.Int (connection));

// Truncate the altitude to a whole number of meters
auto expr = Expr::cast(conn,
  Expr::call(conn, mean_altitude),
  KType::int_(conn));

// Truncate the altitude to a whole number of meters
Expression expr = Expression.cast(
    connection,
    Expression.call(connection, meanAltitude),
    Type.int_(connection));

Expressions are statically typed, with the types of the server’s procedures. Numbers of different types convert to a common type, so an integer multiplies a double directly.

The same conversion applies to a procedure’s arguments, a collection’s elements, a structure’s fields and an assigned variable, and each conversion must widen. Expression.cast() converts a value explicitly, for example to narrow a double to an integer.

The Type class names types, including the classes, enumerations and structures a service defines. Each type of constant has its own factory method, such as Expression.constant_double().

Each operator has a factory method, such as Expression.add(). Expression.and_() and Expression.or_() evaluate both operands. Expression.conditional_and() and Expression.conditional_or() evaluate the second operand only when the first does not decide the result.

Function Streams#

A function whose value can be sent to a client can be streamed:

import time

import krpc

conn = krpc.connect()
vessel = conn.space_center.active_vessel
flight = vessel.flight()

expression = conn.krpc.Expression

# Build a function that computes
# the vessel's altitude in kilometers
expr = expression.divide(
    expression.call(conn.get_call(getattr, flight, "mean_altitude")),
    expression.constant_double(1000),
)

# Stream the value of the function
stream = conn.add_stream(expr)
while True:
    print("Altitude:", stream(), "km")
    time.sleep(1)

Some clients take the type of the stream’s values as a type argument, and others read the function’s return type from the server. A function stream behaves like any other stream, and its rate can be limited in the usual way.

Functions and Collections#

This builds the “any engine out of fuel” event from earlier. The call message only identifies the procedure, so any engine can supply it:

import krpc

conn = krpc.connect()
expression = conn.krpc.Expression
types = conn.krpc.Type

# A function taking an engine, returning true if it is out of fuel

has_fuel = conn.get_call(getattr, vessel.parts.engines[0], "has_fuel")
out_of_fuel = expression.lambda_(
    [engine],
    expression.not_(expression.call_with_arguments(has_fuel, {0: engine})),
)

# Whether any engine satisfies it
engines = conn.get_call(getattr, vessel.parts, "engines")

    event.wait()
    print("An engine has run out of fuel")

using System;
using System.Collections.Generic;
using KRPC.Client;
using KRPC.Client.Services.KRPC;
using Type = KRPC.Client.Services.KRPC.Type;
using KRPC.Client.Services.SpaceCenter;

class Program {
    public static void Main() {
        var connection = new Connection();
        var vessel = connection.SpaceCenter().ActiveVessel;

        // A function taking an engine, returning true if it is out of fuel
        var engine = Expression.Parameter(connection, "engine",
            Type.ClassType(connection, "SpaceCenter", "Engine"));
        var hasFuel = Connection.GetCall(() => vessel.Parts.Engines[0].HasFuel);
        var outOfFuel = Expression.Lambda(connection,
            new List<Expression> { engine },
            Expression.Not(connection,
                Expression.CallWithArguments(connection, hasFuel,
                    new Dictionary<int, Expression> { { 0, engine } })));

        // Whether any engine satisfies it
        var engines = Connection.GetCall(() => vessel.Parts.Engines);
        var expr = Expression.Any(connection,
            Expression.Call(connection, engines), outOfFuel);

        var evnt = connection.AddEvent(expr);
        lock (evnt.Condition) {
            evnt.Wait();
            Console.WriteLine("An engine has run out of fuel");
        }
    }
}

import krpc.client.Connection;
import krpc.client.Event;
import krpc.client.RPCException;
import krpc.client.StreamException;
import krpc.client.services.KRPC.Expression;
import krpc.client.services.KRPC.Type;
import krpc.client.services.SpaceCenter;
import krpc.schema.KRPC.ProcedureCall;

import java.io.IOException;
import java.util.Arrays;
import java.util.Collections;

public class CollectionEvent {
  public static void main(String[] args) throws IOException, RPCException, StreamException {
    try (Connection connection = Connection.newInstance()) {
      SpaceCenter spaceCenter = SpaceCenter.newInstance(connection);
      SpaceCenter.Vessel vessel = spaceCenter.getActiveVessel();

      // A function taking an engine, returning true if it is out of fuel
      Expression engine = Expression.parameter(
        connection, "engine",
        Type.classType(connection, "SpaceCenter", "Engine"));
      ProcedureCall hasFuel = connection.getCall(
        vessel.getParts().getEngines().get(0), "getHasFuel");
      Expression outOfFuel = Expression.lambda(
        connection, Arrays.asList(engine),
        Expression.not(connection, Expression.callWithArguments(
          connection, hasFuel, Collections.singletonMap(0, engine))));

      // Whether any engine satisfies it
      ProcedureCall engines = connection.getCall(vessel.getParts(), "getEngines");
      Expression expr = Expression.any(
        connection, Expression.call(connection, engines), outOfFuel);

      Event event = connection.addEvent(expr);
      synchronized (event.getCondition()) {
        event.waitFor();
        System.out.println("An engine has run out of fuel");
      }
    }
  }
}

A function passed to a collection operation is built from two pieces:

  • Expression.parameter() creates a named, typed parameter. The type can be a class, so a parameter can be an Engine.

  • Expression.lambda_() combines a list of parameters and a body into a function. In the body, the parameter expressions stand for the arguments.

To call an RPC on each element, take the call’s instance from the function’s parameter. Expression.call_with_arguments() embeds a call with some of its arguments given as expressions. Each expression is keyed by the position of its parameter, and position 0 is the instance.

A position without an expression takes the value encoded in the call message, then the parameter’s default. Expression.invoke() calls a function directly, binding values to its parameters by name.

A function from Expression.lambda_() can also be run on its own. Run passes its arguments to the function’s parameters in order, and Expression.parameter_types gives their types.

Expression.select() applies a function to every element, and Expression.where() filters by a predicate. Both produce lazy sequences, which a client cannot decode. Convert one with Expression.to_list() or Expression.to_set() before streaming it. The aggregations, such as Expression.sum() and Expression.any(), take lazy sequences directly.

The Expression class has the other usual collection operations, such as ordering, grouping and set operations, and a constructor for each kind of collection. A function can change a collection in place, with operations such as Expression.append() and Expression.remove().

A dictionary is iterated through its keys or its values. Expression.dictionary_keys() and Expression.dictionary_values() each produce a list. Passing a dictionary to a collection operation is an error that points at them. Expression.contains_key() tests for a key. Expression.get() of a missing key raises a KeyNotFoundException, and of a list index out of range an IndexOutOfRangeException.

The index into a tuple must be a constant. The elements of a tuple differ in type, and Expression.get() takes its result type from the index. A list or a dictionary takes any index expression.

Structures#

A structure a service defines is a value like any other. A function can return, stream, pass and build one. Expression.get_field() reads a field by name:

# The Name field of a structure a call returns
expr = expression.get_field(expression.call(site_info), "Name")

// The Name field of a structure a call returns
var expr = Expression.GetField (connection,
    Expression.Call (connection, siteInfo), "Name");

// The Name field of a structure a call returns
auto expr = Expr::get_field(conn, Expr::call(conn, site_info), "Name");

// The Name field of a structure a call returns
Expression expr = Expression.getField(
    connection, Expression.call(connection, siteInfo), "Name");

Expression.create_struct() builds a structure from its type and its field values, in the order the structure declares them. A field’s name is the one the service declares, as shown in the API documentation.

The compilers produce both nodes from ordinary syntax. Reading a field of a structure compiles to Expression.get_field(), and constructing one compiles to Expression.create_struct().

Statements, Variables and Loops#

This builds and runs total = 0; for x in [1, 2, 3]: total += x, which returns 6:

import krpc

conn = krpc.connect()
expression = conn.krpc.Expression
types = conn.krpc.Type

# total = 0; for x in [1, 2, 3]: total += x
total = expression.variable("total", types.int())
x = expression.variable("x", types.int())
values = expression.create_list([expression.constant_int(i) for i in [1, 2, 3]])
program = expression.block_with_variables(
    [total, x],
    [
        expression.assign(total, expression.constant_int(0)),
        expression.for_each(
            x, values, expression.assign(total, expression.add(total, x))
        ),
        total,
    ],
)

print(conn.run(program))

using System;
using System.Collections.Generic;
using KRPC.Client;
using KRPC.Client.Services.KRPC;
using Type = KRPC.Client.Services.KRPC.Type;

class Program {
    public static void Main() {
        var connection = new Connection();

        // total = 0; foreach (var x in [1, 2, 3]) total += x;
        var total = Expression.Variable(connection, "total", Type.Int(connection));
        var x = Expression.Variable(connection, "x", Type.Int(connection));
        var values = Expression.CreateList(connection, new List<Expression> {
            Expression.ConstantInt(connection, 1),
            Expression.ConstantInt(connection, 2),
            Expression.ConstantInt(connection, 3)
        });
        var program = Expression.BlockWithVariables(
            connection,
            new List<Expression> { total, x },
            new List<Expression> {
                Expression.Assign(connection, total, Expression.ConstantInt(connection, 0)),
                Expression.ForEach(connection, x, values,
                    Expression.Assign(connection, total,
                        Expression.Add(connection, total, x))),
                total
            });

        Console.WriteLine(connection.Run<int>(program));
    }
}

#include <iostream>
#include <vector>
#include <krpc.hpp>
#include <krpc/function_stream.hpp>
#include <krpc/services/krpc.hpp>

int main() {
  auto conn = krpc::connect();

  typedef krpc::services::KRPC::Expression Expr;
  typedef krpc::services::KRPC::Type KType;

  // total = 0; for (auto x : {1, 2, 3}) total += x;
  auto total = Expr::variable(conn, "total", KType::int_(conn));
  auto x = Expr::variable(conn, "x", KType::int_(conn));
  auto values = Expr::create_list(conn, std::vector<Expr>({
    Expr::constant_int(conn, 1),
    Expr::constant_int(conn, 2),
    Expr::constant_int(conn, 3)}));
  auto program = Expr::block_with_variables(
    conn,
    std::vector<Expr>({total, x}),
    std::vector<Expr>({
      Expr::assign(conn, total, Expr::constant_int(conn, 0)),
      Expr::for_each(conn, x, values,
        Expr::assign(conn, total, Expr::add(conn, total, x))),
      total}));

  std::cout << krpc::run<int32_t>(program) << std::endl;
}

import krpc.client.Connection;
import krpc.client.RPCException;
import krpc.client.services.KRPC.Expression;
import krpc.client.services.KRPC.Type;

import java.io.IOException;
import java.util.Arrays;

public class FunctionStatements {
  public static void main(String[] args) throws IOException, RPCException {
    try (Connection connection = Connection.newInstance()) {
      // total = 0; for (int x : new int[] {1, 2, 3}) total += x;
      Expression total = Expression.variable(
        connection, "total", Type.int_(connection));
      Expression x = Expression.variable(connection, "x", Type.int_(connection));
      Expression values = Expression.createList(connection, Arrays.asList(
        Expression.constantInt(connection, 1),
        Expression.constantInt(connection, 2),
        Expression.constantInt(connection, 3)));
      Expression program = Expression.blockWithVariables(
        connection,
        Arrays.asList(total, x),
        Arrays.asList(
          Expression.assign(connection, total,
            Expression.constantInt(connection, 0)),
          Expression.forEach(connection, x, values,
            Expression.assign(connection, total,
              Expression.add(connection, total, x))),
          total));

      int result = connection.run(program);
      System.out.println(result);
    }
  }
}

Statements are ordinary expression nodes. Expression.block_with_variables() sequences statements and declares local variables, and its value is the value of its last statement.

The other statements, such as assignments, if statements, loops and early returns, each have a factory method. A call to a procedure without a return value is a statement, run for its effects.

Object Constants#

Expression.constant_object() embeds a reference to an object, such as a vessel, a reference frame or an engine. A function can compare it for equality, or pass it to a call built with Expression.call_with_arguments(). This event fires when the vessel’s target changes to a particular vessel:

target = conn.get_call(getattr, conn.space_center, "target_vessel")
expr = expression.equal(
    expression.call(target),
    expression.constant_object(krpc.get_object_id(some_vessel)),
)
event = conn.add_event(expr)

var target = Connection.GetCall (() => spaceCenter.TargetVessel);
var expr = Expression.Equal (connection,
    Expression.Call (connection, target),
    Expression.ConstantObject (connection, RemoteObject.GetObjectId (someVessel)));
var evnt = connection.AddEvent (expr);

auto target = sc.target_vessel_call();
auto expr = Expr::equal(conn,
  Expr::call(conn, target),
  Expr::constant_object(conn, krpc::get_object_id(some_vessel)));
auto event = krpc::add_event(expr);

ProcedureCall target = connection.getCall(SpaceCenter.class, "getTargetVessel");
Expression expr = Expression.equal(connection,
    Expression.call(connection, target),
    Expression.constantObject(connection, RemoteObject.getObjectId(someVessel)));
Event event = connection.addEvent(expr);

Expression.constant_object() takes the object’s identifier in the communication protocol. Each client has a function that returns it: krpc.get_object_id in Python and Lua, RemoteObject.GetObjectId in C#, krpc::get_object_id in C++ and RemoteObject.getObjectId in Java. The compilers embed a captured remote object this way.

Exceptions in the Expression API#

Expression.throw() raises an exception, named by its service and class. This builds the fuel check from Exceptions:

amount = conn.get_call(vessel.resources.amount, "LiquidFuel")
expr = expression.if_then(
    expression.less_than(expression.call(amount), expression.constant_double(100)),
    expression.throw(
        "KRPC",
        "InvalidOperationException",
        expression.constant_string("not enough fuel"),
    ),
)
conn.run(expr)

var amount = Connection.GetCall (() => vessel.Resources.Amount ("LiquidFuel"));
var expr = Expression.IfThen (connection,
    Expression.LessThan (connection,
        Expression.Call (connection, amount),
        Expression.ConstantDouble (connection, 100)),
    Expression.Throw (connection, "KRPC", "InvalidOperationException",
        Expression.ConstantString (connection, "not enough fuel")));
connection.Run (expr);

auto expr = Expr::if_then(conn,

Expression.try_catch(), Expression.try_catch_all() and Expression.try_finally() handle exceptions.

Extensibility#

A server side function can call the procedures of every installed service except KRPC, the service that builds and runs the functions. To extend what functions can do, write a service. A service DLL in the game’s plugin folder adds its procedures to server side functions on every client.

The service’s documentation and client stubs are generated in the usual way. The StdLib service is written this way, and ships with the server.

The compilers resolve remote calls through the server’s service definitions. The expression API embeds any procedure with Expression.call_with_arguments().
