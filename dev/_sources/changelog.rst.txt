Changelog
=========


v0.7.0 - unreleased
-------------------


Core
^^^^

* Add extension members: a service can add methods and properties to a class belonging to another service, declared as C# extension methods annotated with ``KRPCMethod`` or ``KRPCProperty`` (:issue:`1077`)
* Add structure types: a compound value with named fields, declared with ``KRPCStruct`` on a C# ``struct`` and sent to the client in full (:issue:`1066`)
* Add a communication protocol carrying protocol buffer messages over a unix domain socket, for clients running on the same machine as the game (:issue:`1065`)
* Add ``KRPC.HoldTick`` and ``KRPC.ReleaseTick``, which hold the game on its current physics tick so a control loop can read, compute and write within one tick (:issue:`1070`)
* Add ``KRPC.NextTick``, which releases the tick being held and holds the one after it (:issue:`1070`)
* Fix the game freezing for as long as a serial connection takes to carry an RPC; serial ports are read and written on their own threads (:issue:`1035`)
* Add ``KRPC.ObjectDestroyedException``, raised when the game object that an object refers to no longer exists (:issue:`1051`)
* Objects whose game objects the game no longer has are removed from the object store when a game state is loaded (:issue:`1051`)
* Fix one server stopping emptying the object store that every server shares, which invalidated the objects held by clients of the servers still running (:issue:`1020`)
* Support for nullable values across all types (:issue:`1017`)
* :breaking:`Breaking` Null values are signaled by an ``is_null`` field rather than by an object id of 0. Class-typed arguments are no longer implicitly nullable (:issue:`1017`)
* Fix a request that names an object the server no longer has leaving the connection stuck (:issue:`1019`)


Server
^^^^^^

* Fix the error from a call that waits on the game being reported as ``Exception has been thrown by the target of an invocation`` (:issue:`1083`)
* Add the ``TickHoldTimeout`` setting, which bounds how long a client may hold the game on one physics tick (:issue:`1070`)
* The server updates before the game collects control inputs, so a control input takes effect on the tick the call is made in (:issue:`1070`)
* :breaking:`Breaking` KSP 1.12.5 is the minimum supported version, matching the maximum (:issue:`1048`)
* Servers can use the local socket protocol, chosen in the server window like any other. No network port is opened (:issue:`1065`)
* Fix the end of a long serial port name being neither visible nor editable in the server window (:issue:`1065`)
* The server is stopped whenever no game is loaded, so a client is disconnected when the player quits to the main menu (:issue:`1041`)
* Fix setting ``KRPC.GameScene`` from one editor straight to the other leaving the flight camera unable to follow a vessel for the rest of the session (:issue:`1038`)
* Sweep objects whose game objects no longer exist out of the object store when the game loads, changes scene or destroys a part or a vessel (:issue:`1051`)


SpaceCenter service
^^^^^^^^^^^^^^^^^^^

* Space center

  * :breaking:`Breaking` ``SpaceCenter.LaunchVessel`` takes its ``crew`` parameter as an exact instruction, and the parameter is optional again. A ``null`` crew uses the craft's default assignments, an empty list launches with no crew, and a populated list seats the named Kerbals in order (:issue:`1017`)
  * :breaking:`Breaking` ``SpaceCenter.Parts.Controlling`` returns ``null`` when the vessel has no control point, rather than its root part (:issue:`1043`)
  * ``SpaceCenter.Control.State``, ``SpaceCenter.Control.Source`` and the members of ``SpaceCenter.Comms`` report no control and no communications for a vessel with no node in the communication network, rather than throwing (:issue:`1043`)
  * ``SpaceCenter.Control.Source`` is ``None`` whenever ``SpaceCenter.Control.State`` is ``None`` (:issue:`1043`)
  * ``SpaceCenter.Control.State`` and ``SpaceCenter.Control.Source`` are taken from the control level that KSP gates a vessel's control on, rather than from its node in the communication network (:issue:`1043`)
  * ``SpaceCenter.Decoupler.Decouple`` returns the separated vessel when it fires an omni-decoupler such as a stack separator (:issue:`1043`)
  * Working with many stages, vessel resources, communication links or resource converters no longer slows the server down (:issue:`1071`)

* Editor

  * Add ``SpaceCenter.Editor``, available in the vehicle assembly building and the space plane hangar, for inspecting the vessel that is being constructed. ``Editor.LoadVessel`` loads a craft file into the open editor (:issue:`1038`)
  * ``Editor.LaunchVessel`` launches the vessel that is being constructed, with the same crew, recovery and mission flag options as ``SpaceCenter.LaunchVessel`` (:issue:`1038`)
  * ``EditorVessel.Parts`` gives the parts tree of the vessel under construction. The members of ``Part`` and the part-type classes that describe the design are available (:issue:`1038`)
  * ``EditorVessel.Stages``, ``EditorVessel.StageAt``, ``EditorVessel.DecoupleStages`` and ``EditorVessel.DecoupleStageAt`` give the vessel's stages, with the same figures that ``Stage`` reports in flight (:issue:`1038`)
  * Add ``EditorVessel.DeltaV``, ``VacuumDeltaV``, ``SeaLevelDeltaV`` and ``BurnTime`` for the whole vessel, and ``EditorVessel.DeltaVReady``, which reports whether the figures are current (:issue:`1038`)
  * ``Editor.DeltaVBody``, ``Editor.DeltaVAltitude`` and ``Editor.DeltaVSituation`` set the situation those figures assume (:issue:`1038`)
  * ``EditorVessel.Resources``, ``Part.Resources`` and ``Stage.Resources`` report the resources the vessel under construction can hold (:issue:`1038`)
  * A part of the vessel under construction raises ``KRPC.ObjectDestroyedException`` once it is no longer in that vessel, and once the editor has loaded any vessel over it (:issue:`1051`)
  * Add ``EditorVessel.CenterOfMass``, ``EditorVessel.MomentOfInertia`` and ``EditorVessel.InertiaTensor``. ``Part.MomentOfInertia`` and ``Part.InertiaTensor`` are available in the editor as well (:issue:`1059`)
  * ``Part.Mass`` and ``Part.DryMass`` no longer report 1000 kg for every part in the editor (:issue:`1059`)
  * ``Part.Position``, ``Part.CenterOfMass``, ``Part.ReferenceFrame`` and ``Part.CenterOfMassReferenceFrame`` are available in the editor (:issue:`1064`)

* Vessels and crew

  * ``Vessel.InertiaTensor`` is restricted to the flight scene, as ``Vessel.MomentOfInertia`` already is. Outside flight it returned zeros (:issue:`1059`)
  * Add ``CrewMember.EVA``, which sends a Kerbal outside through the hatch of the part it is in and returns the vessel it becomes (:issue:`319`)
  * Add ``Vessel.Terminate``, which removes a vessel and its parts from the game without recovering anything (:issue:`1034`)
  * ``Vessel.Recover`` recovers non-active vessels without switching to the space center scene, and the mission completion dialog is auto-closed (:issue:`1021`)
  * Add ``Vessel.OrbitSpeedReferenceFrame``, ``Vessel.SurfaceSpeedReferenceFrame`` and ``Vessel.TargetSpeedReferenceFrame``, one per navball speed mode. The velocity of the vessel in one of these is the velocity the navball shows in that mode (:issue:`1029`)
  * Using a vessel that no longer exists raises ``KRPC.ObjectDestroyedException`` (:issue:`1051`)
  * A ``CrewMember`` looks the kerbal up on the game's roster on every call, so one obtained before a load goes on working (:issue:`1051`)
  * Renaming a kerbal destroys every object for them, which have to be obtained again under the new name (:issue:`1051`)

* Staging

  * Fix stages from ``Vessel.Stages``, ``Vessel.StageAt``, ``Vessel.DecoupleStages`` and ``Vessel.DecoupleStageAt`` breaking after a Revert to Launch (:issue:`1023`)
  * The delta-v figures on ``Vessel`` and ``Stage`` ask the game to calculate them, so they are available in flight without opening the game's own delta-v app first (:issue:`1076`)
  * Add ``Vessel.RecalculateDeltaV``, which recalculates the figures and waits for them, and ``Vessel.DeltaVReady``, which reports whether they are current (:issue:`1076`)

* Autopilot

  * Setting ``AutoPilot.TargetDirection`` keeps the target roll, rather than clearing it (:issue:`1054`)
  * The auto-pilot's control loop runs at a defined point in the server's update, so a target set during a tick is flown on that tick. ``AutoPilot.UpdateMode`` chooses that point (:issue:`1070`)
  * Fix an engaged auto-pilot failing on every physics tick once the vessel or part its ``AutoPilot.ReferenceFrame`` is defined against is gone (:issue:`1070`)

* Orbits, nodes and bodies

  * An ``Orbit`` reads the orbit of the vessel, celestial body or maneuver node it belongs to as it is now, so it keeps working across a load (:issue:`764`)
  * A ``ClosestApproach`` is freed once either of the orbits it describes is gone (:issue:`1051`)
  * Add ``CelestialBody.SurfaceNormal``, ``CelestialBody.BedrockNormal`` and ``CelestialBody.MSLNormal``, the slope of the terrain at a given latitude and longitude (:issue:`1030`)
  * Fix ``ClosestApproach.Velocity`` and ``ClosestApproach.TargetVelocity`` being offset by the velocity of the frame the active vessel's reference body moves in (:issue:`1047`)
  * Add ``Orbit.CreateFromPositionAndVelocity`` and ``Orbit.CreateFromOrbitalElements``, which build an orbit that coasts freely under gravity without an object in the game to follow (:issue:`1046`)
  * Add ``Orbit.ReferenceFrame`` and ``Orbit.OrbitalReferenceFrame``, centered on the point an orbit has reached at the current time (:issue:`1046`)
  * Add ``Orbit.Remove``, which releases the memory the server holds for a created orbit (:issue:`1072`)
  * :breaking:`Breaking` A ``ClosestApproach`` reads the two orbits as they are now, so its estimate follows them as the game runs. Asking for the same approach again gives the same object (:issue:`1072`)
  * Add ``Orbit.VelocityAt``, giving the velocity at a given time in a given reference frame (:issue:`1046`)
  * ``Orbit.Epoch`` is documented as the universal time at which the mean anomaly at epoch is measured. It was described as the time since that point (:issue:`1046`)
  * Fix ``Orbit.OrbitalSpeed``, which reported the speed the vessel had when it was last on rails (:issue:`1086`)
  * Add ``Orbit.SpeedAt`` and ``Orbit.SpecificEnergy``, the speed at a given universal time and the specific orbital energy (:issue:`1086`)
  * :breaking:`Breaking` ``Orbit.OrbitalSpeedAt`` takes a universal time, in a parameter renamed from ``time`` to ``ut``. It took the time since the orbit's periapsis. Deprecated in favor of ``Orbit.SpeedAt`` (:issue:`1086`)
  * :deprecated:`Deprecated` ``Orbit.OrbitalSpeed`` and ``Orbit.OrbitalEnergy``, superseded by ``Orbit.Speed`` and ``Orbit.SpecificEnergy`` (:issue:`1086`)

* Maneuver nodes

  * Using a maneuver node that has been removed raises ``KRPC.ObjectDestroyedException``. Loading a game replaces the vessel's maneuver nodes (:issue:`1051`)
  * Fix removing a maneuver node leaking the object for the rest of the session (:issue:`771`)

* Reference frames

  * Add ``ReferenceFrame.Remove``, which releases the memory the server holds for a created frame (:issue:`1072`)
  * ``ReferenceFrame.CreateRelative`` and ``ReferenceFrame.CreateHybrid`` return a new frame on each call, which is the creating client's own to remove (:issue:`1072`)
  * ``ReferenceFrame.CreateRelative`` and ``ReferenceFrame.CreateHybrid`` raise an error when given no frame to be defined against (:issue:`1072`)
  * Creating many hybrid reference frames no longer slows the server down (:issue:`1071`)
  * A reference frame taken from a docking port keeps working across a quickload (:issue:`885`, :issue:`764`)

* Flight and aerodynamics

  * Add ``Flight.SurfaceNormal``, the slope of the terrain under a vessel (:issue:`1030`)
  * Fix ``Flight.AerodynamicForce`` and ``Flight.AerodynamicAcceleration`` turning with the roll of the vessel when Ferram Aerospace Research is installed (:issue:`1032`)
  * Add ``Flight.SideForce``, the part of ``Flight.AerodynamicForce`` that acts across the air stream and out of the vessel's side (:issue:`1032`)
  * Fix ``Flight.Lift`` and ``Flight.LiftAcceleration`` reporting a force scaled by the cosine squared of the sideslip angle (:issue:`1032`)
  * ``Flight.AerodynamicTorque`` works with Ferram Aerospace Research installed (:issue:`1032`)
  * Fix ``Flight.SimulateAerodynamicForceAt``, ``Flight.SimulateAerodynamicTorqueAt`` and ``Flight.SimulateAerodynamicWrenchAt`` returning ``NaN`` with Ferram Aerospace Research installed when there is no relative airflow (:issue:`1032`)
  * Fix ``Flight.StallFraction`` returning ``NaN`` for a vessel with no lifting surfaces (:issue:`1032`)

* Control

  * A Kerbal on EVA can be driven through ``Vessel.Control``. The translation inputs walk it about and fly its jetpack, ``Control.RCS`` deploys and stows the jetpack, and ``Control.Lights`` switches the helmet lamp (:issue:`319`)
  * Add ``Control.Board`` and ``Control.Airlock``, for the part whose hatch a Kerbal on EVA is standing at, and ``Control.GrabLadder``, ``Control.ReleaseLadder`` and ``Control.Ladder`` for the ladder it is alongside (:issue:`319`)
  * Setting ``Control.StageLock`` leaves the in-game Alt+L shortcut in step with it (:issue:`1022`)
  * Add ``Control.PrecisionMode``, the precision control mode that the Caps Lock key toggles (:issue:`1082`)

* Parts

  * :breaking:`Breaking` ``RCS.TranslationOverride`` thrusts along the right, up and forward axes it documents (:issue:`1080`)
  * Add ``RCS.Force`` and ``RCS.Torque``, the force and torque a block is applying, and ``RCS.OverrideForce`` and ``RCS.OverrideTorque``, what a given demand would apply (:issue:`1080`)
  * Add ``Thruster.Thrust``, the thrust a single nozzle of an engine or RCS block is producing (:issue:`1080`)
  * ``RCS.AvailableForce`` and ``RCS.AvailableTorque``, and the vessel level force, torque and acceleration properties that include them, account for precision mode (:issue:`1082`)
  * Precision mode leaves a block driven by ``RCS.InputOverride`` at full thrust (:issue:`1082`)
  * ``RCS.Thrusters``, ``RCS.AvailableForce`` and ``RCS.AvailableTorque`` count only the nozzles of the part's selected variant (:issue:`1079`)
  * ``Decoupler.IsOmniDecoupler`` reports what the part is configured as for every decoupler, including radial ones. It was false for all of them (:issue:`1048`)
  * A force added with ``Part.AddForce`` stops being applied, and is freed, once its part is destroyed (:issue:`1051`)
  * ``Force.Remove`` leaves the object gone, so using one afterwards raises ``KRPC.ObjectDestroyedException`` (:issue:`1051`)
  * ``Part.BoundingBox`` and ``Vessel.BoundingBox`` measure only the meshes of a part's own model, leaving out physicsless child parts and objects another mod has attached (:issue:`1024`)
  * Computing a bounding box no longer duplicates the meshes of every part it measures (:issue:`1024`)
  * Add support for [RealFuels](https://forum.kerbalspaceprogram.com/index.php?/topic/58236-\*), reported by ``SpaceCenter.RealFuelsAvailable``. On an engine it manages, ``Engine.Ignitions``, ``Engine.IgnitionResources``, ``Engine.HasUllage``, ``Engine.PropellantStability``, ``Engine.PropellantReliability``, ``Engine.PressureFed`` and ``Engine.HasFeedPressure`` are available; on a tank, ``Part.HighlyPressurized`` and ``Part.BoiloffRate`` (:issue:`1039`)
  * Fix ``ReactionWheel.AvailableTorque``, and the vessel level torque properties that include it, being scaled by the square of the wheel's authority limiter when KSPCommunityFixes is installed (:issue:`1042`)
  * Fix ``Decoupler`` objects accumulating for the rest of the session, and the same decoupler obtained twice comparing unequal (:issue:`1051`)
  * A ``Decoupler`` finds its part's decoupler module again on every call, so it keeps working across a quickload (:issue:`1051`)
  * Using a part that has been destroyed raises ``KRPC.ObjectDestroyedException`` instead of failing with a null reference (:issue:`885`)
  * Using a part module, or an object built on one such as ``Engine`` or ``Parachute``, after its part has been destroyed raises ``KRPC.ObjectDestroyedException`` (:issue:`885`)
  * Part modules, and the objects built on them, read the modules of the loaded game, so they keep working across a quickload (:issue:`764`)
  * Using a part of a vessel that the game has unloaded raises an error saying that the part is not loaded (:issue:`1051`)
  * The fields, events and actions of a part module read the loaded game's module (:issue:`764`)
  * A ``ScienceSubject`` belongs to the game state it was read from, and using one after that state has been replaced raises ``KRPC.ObjectDestroyedException`` (:issue:`771`)
  * Fix ``Experiment.ScienceSubject`` adding a new object for every read (:issue:`771`)
  * Fix ``ScienceSubject.Science`` and ``ScienceSubject.ScienceCap`` scaling by the science gain multiplier that was in force when the object was read (:issue:`1051`)
  * Make ``ModuleRef`` public, for a mod that exposes a part module as a class of its own service (:issue:`1077`)

* Resources

  * Add ``ResourceTransfer.Cancel`` to stop a transfer before it finishes (:issue:`1028`)
  * Fix a resource transfer failing on every update, and never completing, once one of the parts it runs between is destroyed (:issue:`1051`)
  * Add ``ResourceTransfer.Remove``, which stops a transfer and releases the memory the server holds for it (:issue:`1072`)

* Camera

  * ``Camera.NextCamera`` and ``Camera.PreviousCamera`` move the IVA view between the crew of the active vessel without dropping out of IVA mode (:issue:`1031`)
  * Setting ``Camera.FocussedCrewMember`` to the crew member already in view no longer switches to the flight camera. Setting it to one who is not in view of a part interior raises an error (:issue:`1031`)
  * ``Camera.FocussedCrewMember`` returns ``null`` when no crew member is in view (:issue:`1031`)

* Alarms, contracts and waypoints

  * ``SpaceCenter.Alarm``, ``Contract``, ``ContractParameter`` and ``Waypoint`` objects look their record up on every call, so they keep working when the game rebuilds it. One the game no longer has raises ``KRPC.ObjectDestroyedException`` (:issue:`1051`)

* Communications

  * A ``CommLink`` is identified by the two nodes it joins and reports the link between them as it is now. One whose nodes are gone raises ``KRPC.ObjectDestroyedException`` (:issue:`1051`)

User Interface service
^^^^^^^^^^^^^^^^^^^^^^

* :breaking:`Breaking` Removing a user interface element another client created, or one the server no longer holds, reports that it is not among those this client created (:issue:`1072`)
* :breaking:`Breaking` Colors are given as ``(red, green, blue, alpha)`` rather than ``(red, green, blue)``, so an element can be drawn translucent. Affects ``Text.Color`` and the color of a ``UI.Message`` (:issue:`1040`)
* :breaking:`Breaking` ``InputField.Changed`` is only set when the user types in the field (:issue:`1040`)
* :breaking:`Breaking` User interface elements are drawn using the skin the game draws its own interface in, so the size and color that ``Text`` starts out with are not fixed values (:issue:`1040`)
* :breaking:`Breaking` ``Visible`` is the element's own setting. An element is drawn when everything it is inside is visible as well, so an interface can be built inside a hidden panel and shown all at once (:issue:`1040`)
* User interface elements can be created in every game scene (:issue:`1040`)
* User interface elements are removed when the game scene changes (:issue:`1040`)
* Add ``Interactable`` to every control, to gray one out and stop it responding to the user (:issue:`1040`)
* Add ``Toggle``, a check box, and ``ToggleGroup``, which makes a set of toggles behave as radio buttons. A group refers to its toggles rather than containing them (:issue:`1040`)
* Add ``Layout`` to arrange the contents of a ``Panel`` in a row, a column or a grid. ``Panel.AddHorizontalLayout``, ``Panel.AddVerticalLayout`` and ``Panel.AddGridLayout`` create one (:issue:`1040`)
* Add ``Slider``, ``Dropdown`` and ``Image``. An image shows the contents of a PNG or JPEG file, or a plain colored rectangle (:issue:`1040`)
* Add ``Panel.Style``, to draw a panel as a box rather than a window, and ``Panel.Color`` (:issue:`1040`)
* Add ``Panel.Draggable``, so a panel can be moved by the user and used as a window (:issue:`1040`)
* Add ``ScrollView``, a view onto a panel larger than the space available for it (:issue:`1040`)
* Add ``LayoutElement``, for how much space a user interface object asks a layout for, and ``Panel.SizeFitter``, for sizing a panel to fit what it contains (:issue:`1040`)
* Add ``InputField.Placeholder``, the hint drawn in an input field while it is empty (:issue:`1040`)
* Add ``InputField.ContentType``, filtering what the user can type into a field as they type it, along with ``InputField.CharacterLimit`` and ``InputField.ReadOnly`` (:issue:`1040`)
* Add ``Color`` to every control, tinting the sprite it is drawn with (:issue:`1040`)
* Add ``Tooltip`` to every control, a short piece of text shown beside the pointer while it rests on the control (:issue:`1040`)
* Add ``Panel.BringToFront``, to draw a panel in front of the elements beside it. A draggable panel also brings itself to the front when the user presses it (:issue:`1040`)
* ``AddSlider`` can create a vertical slider, running from bottom to top (:issue:`1040`)
* Add ``Button.Pressed``, true while the user is holding the button down (:issue:`1040`)
* Add ``Text.WordWrap``, so a value label can be kept to one line (:issue:`1040`)
* Add ``Image.SetPixels``, drawing a picture from raw pixels rather than a file. ``Image.UpdatePixels`` redraws a block of the picture and leaves the rest (:issue:`1040`)
* Two user interface objects that refer to the same element compare equal (:issue:`1040`)
* A canvas added with ``UI.AddCanvas`` follows the interface scale the player has set, as the stock canvas does (:issue:`1040`)
* Fix ``Text.Font`` making a font of its own every time it is set, and leaving it behind when the label went. A font of a given name is made once and shared (:issue:`1040`)
* A user interface object raises ``KRPC.ObjectDestroyedException`` once its element is gone, which removing it, ``UI.Clear``, the client that made it disconnecting and changing scene all do (:issue:`1051`)
* ``RectTransform``, ``Layout``, ``LayoutElement`` and ``SizeFitter`` do the same once the element they were taken from is gone, and are dropped with it (:issue:`1051`)
* Fix ``RectTransform`` objects accumulating for the rest of the session. Reading the same one twice gives the same object (:issue:`1051`)

C-nano client
^^^^^^^^^^^^^

* Support structure types, generated as a C struct with a member per field (:issue:`1066`)
* :breaking:`Breaking` Support null for any nullable type; a nullable non-class return adds a ``bool* returnValueIsNull`` out-parameter and a nullable argument is a pointer (:issue:`1017`)
* Add ``KRPC_COMMUNICATION_TCP``, building the library to communicate over TCP/IP. A connection is opened with a ``krpc_connection_config_t`` in place of a port name (:issue:`1055`)
* Add a ``tcp`` feature to the vcpkg port; ``vcpkg install "krpc-cnano[tcp]"`` (:issue:`1055`)
* Add ``KRPC_COMMUNICATION_LOCALSOCKET`` and a ``localsocket`` vcpkg feature, building the library to communicate over a unix domain socket (:issue:`1065`)
* Add ``KRPC_SINGLE_CONNECTION``, for a ``KRPC_COMMUNICATION_CUSTOM`` mechanism that opens its own connection to each server (:issue:`1055`)
* Reduce the cost of a remote procedure call, from tens of reads and writes to one write and two reads (:issue:`1056`)
* Add ``KRPC_BUFFER_SIZE``, how much of a message to hold in memory while it is sent or received. Defaults to 1024 bytes, and to 128 on Arduino (:issue:`1056`)
