KRPC
====













.. module:: KRPC

Main kRPC service, used by clients to interact with basic server functionality.


.. staticmethod:: get_client_id()

   Returns the identifier for the current client.

   :rtype: string




.. staticmethod:: get_client_name()

   Returns the name of the current client.
   This is an empty string if the client has no name.

   :rtype: string




.. attribute:: clients: List

   A list of RPC clients that are currently connected to the server.
   Each entry in the list is a clients identifier, name and address.

   :Attribute: Read-only, cannot be set
   :rtype: List




.. staticmethod:: get_status()

   Returns some information about the server, such as the version.

   :rtype: :class:`krpc.schema.KRPC.Status`




.. staticmethod:: get_services()

   Returns information on all services, procedures, classes, properties etc. provided by the server.
   Can be used by client libraries to automatically create functionality such as stubs.

   :rtype: :class:`krpc.schema.KRPC.Services`




.. staticmethod:: hold_tick()

   Hold the game on its current physics tick until :meth:`KRPC.release_tick` is called
   or the hold times out. Every call made in between is executed before the game moves
   on, so that a program which reads the game state, computes with it and writes the
   result back does all three in the state of a single tick.

   A tick is held once and no more, so this waits for the next tick when the current
   one has already been held and let go.


   .. note::

      The game renders no frame, takes no input and runs no physics while the tick is
      held, so a hold should be as short as the program can make it, and should be
      released even when the code between the two calls fails. Only one client can hold
      the tick at a time, and only a client making a call can hold it: the tick cannot be
      held by a stream or an event. A hold ends by itself when it times out, when the
      client disconnects, or when the client calls a procedure that takes more than one
      tick to finish, such as staging or warping, since such a call can only finish in the
      tick the hold is holding back. Waiting for a stream or an event while holding the
      tick therefore waits out the timeout, as stream updates are only sent once the tick
      has been let go.




.. staticmethod:: release_tick()

   Let the game move on from the tick that :meth:`KRPC.hold_tick` held it on. Does
   nothing if the tick is not being held, which is what a client whose hold has already
   ended sees.





.. staticmethod:: next_tick()

   Let the game move on from the tick being held and hold the one after it, so that a
   program acts on consecutive physics ticks. Holds the soonest tick it can if no tick
   is currently being held.


   .. note::

      A release and a hold made as two separate calls leave the server free to advance
      between them, since the hold is a call it has to be waiting for when it looks. This
      takes the next tick without that gap, so it is the call a loop that has to act on
      every tick is built around: call it at the top of the loop, work, and come back to
      it. The game advances one tick per call and no faster, so it runs at the rate of the
      loop for as long as the loop runs, and the loop ends by calling
      :meth:`KRPC.release_tick`.

      Every other limit of :meth:`KRPC.hold_tick` applies unchanged, the timeout
      included. A hold lost to the timeout is not reported: the next call simply takes
      whatever tick it lands on.




.. attribute:: game_scene: KRPC.GameScene

   The current game scene. Setting this switches the game to the given
   scene, or opens/closes the corresponding facility for the pseudo-scenes.
   Scene changes happen asynchronously: setting this property returns
   immediately, and clients should poll it until it reports the requested
   scene. Setting it to :attr:`KRPC.GameScene.flight` resumes the save's
   active vessel, and fails if there is none. Moving between
   :attr:`KRPC.GameScene.editor_vab` and :attr:`KRPC.GameScene.editor_sph`
   keeps the vessel that is being constructed, as the game's own switch
   editor button does.

   :Attribute: Can be read or written
   :rtype: :class:`KRPC.GameScene`




.. attribute:: current_game_scene: KRPC.GameScene

   .. warning:: Deprecated. Use :attr:`KRPC.game_scene <KRPC.KRPC.game_scene>` instead.

   Get the current game scene.

   :Attribute: Read-only, cannot be set
   :rtype: :class:`KRPC.GameScene`




.. attribute:: paused: boolean

   Whether the game is paused.

   :Attribute: Can be read or written
   :rtype: boolean





.. class:: GameScene

   The game scene. See :attr:`KRPC.game_scene <KRPC.KRPC.game_scene>`.


   .. data:: space_center

      The game scene showing the Kerbal Space Center buildings.


   .. data:: flight

      The game scene showing a vessel in flight (or on the launchpad/runway).


   .. data:: tracking_station

      The tracking station.


   .. data:: editor_vab

      The Vehicle Assembly Building.


   .. data:: editor_sph

      The Space Plane Hangar.


   .. data:: mission_builder

      The mission builder.


   .. data:: astronaut_complex

      The astronaut complex. This is a pseudo-scene, shown when the
      astronaut complex facility is open within the space center scene.


   .. data:: mission_control

      Mission control. This is a pseudo-scene, shown when the
      mission control facility is open within the space center scene.


   .. data:: research_and_development

      Research and development. This is a pseudo-scene, shown when the
      research and development facility is open within the space center scene.


   .. data:: administration

      The administration facility. This is a pseudo-scene, shown when the
      administration facility is open within the space center scene.



.. class:: InvalidOperationException

   A method call was made to a method that is invalid
   given the current state of the object.



.. class:: ArgumentException

   A method was invoked where at least one of the passed arguments does not
   meet the parameter specification of the method.



.. class:: ArgumentNullException

   A null reference was passed to a method that does not accept it as a valid argument.



.. class:: ArgumentOutOfRangeException

   The value of an argument is outside the allowable range of values as defined by the invoked method.



.. class:: ObjectDestroyedException

   The game object that a service object refers to no longer exists,
   so the object cannot be used. For example, the part it represents
   was destroyed, or the vessel it belongs to was recovered.
