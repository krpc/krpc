Orbit#

public class Orbit#

Describes an orbit. For example, the orbit of a vessel, obtained by calling Vessel.getOrbit(), or a celestial body, obtained by calling CelestialBody.getOrbit().

static Orbit createFromPositionAndVelocity(Connection connection, CelestialBody body, org.javatuples.Triplet<Double, Double, Double> position, org.javatuples.Triplet<Double, Double, Double> velocity, double ut, ReferenceFrame referenceFrame)#

Create the orbit that passes through a given position at a given velocity. The orbit coasts freely under the gravity of the body being orbited, so it describes where an object left to fall from that position and velocity would be at any later time.

Parameters:

  • body (CelestialBody) – The celestial body being orbited.

  • position (org.javatuples.Triplet) – The position, as a position vector.

  • velocity (org.javatuples.Triplet) – The velocity, as a vector pointing in the direction of travel, whose magnitude is the speed in meters per second.

  • ut (double) – The universal time, in seconds, at which the object is at position traveling at velocity.

  • referenceFrame (ReferenceFrame) – The reference frame that position and velocity are in. Defaults to CelestialBody.getNonRotatingReferenceFrame() of body.

Note

The orbit is a single conic around body. It never changes sphere of influence, so Orbit.getNextOrbit() is null, and no atmosphere slows it. A vessel held on rails follows its own orbit exactly, while one inside the physics bubble is simulated and drifts from it a little.

Orbit.getRadius(), Orbit.getSpeed(), Orbit.getTrueAnomaly(), Orbit.getTimeToApoapsis() and the like describe the orbit at ut and stay there. Use Orbit.radiusAt(double), Orbit.speedAt(double), Orbit.positionAt(double, ReferenceFrame), Orbit.velocityAt(double, ReferenceFrame) and Orbit.trueAnomalyAtUT(double) for another time, and Orbit.getReferenceFrame() and Orbit.getOrbitalReferenceFrame() to follow the orbit as time passes.

The orbit is held until Orbit.remove() is called on it or the client that created it disconnects. Remove each one created by a script that creates them repeatedly, for example once per update.

static Orbit createFromOrbitalElements(Connection connection, CelestialBody body, double semiMajorAxis, double eccentricity, double inclination, double longitudeOfAscendingNode, double argumentOfPeriapsis, double meanAnomalyAtEpoch, double epoch)#

Create the orbit with the given orbital elements around a given body. The orbit coasts freely under the gravity of that body, so it describes where an object on it would be at any time.

Parameters:

  • body (CelestialBody) – The celestial body being orbited.

  • semiMajorAxis (double) – The semi-major axis of the orbit, in meters. Positive for an ellipse and negative for a hyperbola.

  • eccentricity (double) – The eccentricity of the orbit. Below one for an ellipse and above one for a hyperbola.

  • inclination (double) – The inclination of the orbit, in radians.

  • longitudeOfAscendingNode (double) – The longitude of the ascending node, in radians.

  • argumentOfPeriapsis (double) – The argument of periapsis, in radians.

  • meanAnomalyAtEpoch (double) – The mean anomaly at epoch, in radians.

  • epoch (double) – The universal time, in seconds, that meanAnomalyAtEpoch is measured at.

Note

The orbit is a single conic around body. It never changes sphere of influence, so Orbit.getNextOrbit() is null, and no atmosphere slows it.

The angles are measured against the reference plane and direction that Orbit.getInclination(), Orbit.getLongitudeOfAscendingNode() and Orbit.getArgumentOfPeriapsis() report them against. Orbit.referencePlaneNormal(ReferenceFrame) and Orbit.referencePlaneDirection(ReferenceFrame) give these as vectors in a reference frame.

Orbit.getRadius(), Orbit.getSpeed(), Orbit.getTrueAnomaly(), Orbit.getTimeToApoapsis() and the like describe the orbit at epoch and stay there. Use Orbit.radiusAt(double), Orbit.speedAt(double), Orbit.positionAt(double, ReferenceFrame), Orbit.velocityAt(double, ReferenceFrame) and Orbit.trueAnomalyAtUT(double) for another time, and Orbit.getReferenceFrame() and Orbit.getOrbitalReferenceFrame() to follow the orbit as time passes.

The orbit is held until Orbit.remove() is called on it or the client that created it disconnects. Remove each one created by a script that creates them repeatedly, for example once per update.

void remove()#

Remove the orbit, releasing the memory the server holds for it.

Note

Only an orbit created by Orbit.createFromPositionAndVelocity(CelestialBody, org.javatuples.Triplet<Double,Double,Double>, org.javatuples.Triplet<Double,Double,Double>, double, ReferenceFrame) or Orbit.createFromOrbitalElements(CelestialBody, double, double, double, double, double, double, double) can be removed. Every other orbit belongs to something in the game, and the server holds one of each.

Any further use of this object throws an exception, as does use of a reference frame defined against it. An orbit belongs to the client that created it, and is removed when that client disconnects.

The celestial body (e.g. planet or moon) around which the object is orbiting.

ReferenceFrame getReferenceFrame()#

The reference frame that moves along the orbit, and is orientated in a fixed direction.

  • The origin is at the point the orbit has reached at the current time.

  • The axes do not rotate. They point in the same fixed directions as those of CelestialBody.getNonRotatingReferenceFrame() of Orbit.getBody().

Note

For the orbit of a vessel, the origin is the point the vessel’s orbit has reached rather than the vessel’s own center of mass. The two are a few meters apart, as a vessel inside the physics bubble is simulated rather than being held on its orbit.

ReferenceFrame getOrbitalReferenceFrame()#

The reference frame that moves along the orbit, and is orientated with its prograde/normal/radial directions.

  • The origin is at the point the orbit has reached at the current time.

  • The axes rotate with the orbital prograde/normal/radial directions.

  • The x-axis points in the orbital anti-radial direction.

  • The y-axis points in the orbital prograde direction.

  • The z-axis points in the orbital normal direction.

Note

For the orbit of a vessel, the origin is the point the vessel’s orbit has reached rather than the vessel’s own center of mass, which is what Vessel.getOrbitalReferenceFrame() is centered on.
