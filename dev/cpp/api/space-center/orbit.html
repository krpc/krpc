Orbit#

class Orbit#

Describes an orbit. For example, the orbit of a vessel, obtained by calling Vessel::orbit(), or a celestial body, obtained by calling CelestialBody::orbit().

static Orbit create_from_position_and_velocity(Client &connection, CelestialBody body, std::tuple<double, double, double> position, std::tuple<double, double, double> velocity, double ut, ReferenceFrame reference_frame)#

Create the orbit that passes through a given position at a given velocity. The orbit coasts freely under the gravity of the body being orbited, so it describes where an object left to fall from that position and velocity would be at any later time.

Parameters:

  • body – The celestial body being orbited.

  • position – The position, as a position vector.

  • velocity – The velocity, as a vector pointing in the direction of travel, whose magnitude is the speed in meters per second.

  • ut – The universal time, in seconds, at which the object is at position traveling at velocity.

  • reference_frame – The reference frame that position and velocity are in. Defaults to CelestialBody::non_rotating_reference_frame() of body.

Note

The orbit is a single conic around body. It never changes sphere of influence, so Orbit::next_orbit() is NULL, and no atmosphere slows it. A vessel held on rails follows its own orbit exactly, while one inside the physics bubble is simulated and drifts from it a little.

Orbit::radius(), Orbit::speed(), Orbit::position(), Orbit::velocity() and the like describe the orbit at ut and stay there. Use Orbit::radius_at(), Orbit::speed_at(), Orbit::position_at(), Orbit::velocity_at() and Orbit::true_anomaly_at_ut() for another time, and Orbit::reference_frame() and Orbit::orbital_reference_frame() to follow the orbit as time passes.

The orbit is held until Orbit::remove() is called on it or the client that created it disconnects. Remove each one created by a script that creates them repeatedly, for example once per update.

static Orbit create_from_orbital_elements(Client &connection, CelestialBody body, double semi_major_axis, double eccentricity, double inclination, double longitude_of_ascending_node, double argument_of_periapsis, double mean_anomaly_at_epoch, double epoch)#

Create the orbit with the given orbital elements around a given body. The orbit coasts freely under the gravity of that body, so it describes where an object on it would be at any time.

Parameters:

  • body – The celestial body being orbited.

  • semi_major_axis – The semi-major axis of the orbit, in meters. Positive for an ellipse and negative for a hyperbola.

  • eccentricity – The eccentricity of the orbit. Below one for an ellipse and above one for a hyperbola.

  • inclination – The inclination of the orbit, in radians.

  • longitude_of_ascending_node – The longitude of the ascending node, in radians.

  • argument_of_periapsis – The argument of periapsis, in radians.

  • mean_anomaly_at_epoch – The mean anomaly at epoch, in radians.

  • epoch – The universal time, in seconds, that mean_anomaly_at_epoch is measured at.

Note

The orbit is a single conic around body. It never changes sphere of influence, so Orbit::next_orbit() is NULL, and no atmosphere slows it.

The angles are measured against the reference plane and direction that Orbit::inclination(), Orbit::longitude_of_ascending_node() and Orbit::argument_of_periapsis() report them against. Orbit::reference_plane_normal() and Orbit::reference_plane_direction() give these as vectors in a reference frame.

Orbit::radius(), Orbit::speed(), Orbit::position(), Orbit::velocity() and the like describe the orbit at epoch and stay there. Use Orbit::radius_at(), Orbit::speed_at(), Orbit::position_at(), Orbit::velocity_at() and Orbit::true_anomaly_at_ut() for another time, and Orbit::reference_frame() and Orbit::orbital_reference_frame() to follow the orbit as time passes.

The orbit is held until Orbit::remove() is called on it or the client that created it disconnects. Remove each one created by a script that creates them repeatedly, for example once per update.

void remove()#

Remove the orbit, releasing the memory the server holds for it.

Note

Only an orbit created by Orbit::create_from_position_and_velocity() or Orbit::create_from_orbital_elements() can be removed. Every other orbit belongs to something in the game, and the server holds one of each.

Any further use of this object throws an exception, as does use of a reference frame defined against it. An orbit belongs to the client that created it, and is removed when that client disconnects.

CelestialBody body()#

The celestial body (e.g. planet or moon) around which the object is orbiting.

ReferenceFrame reference_frame()#

The reference frame that moves along the orbit, and is orientated in a fixed direction.

  • The origin is at the point the orbit has reached at the current time.

  • The axes do not rotate. They point in the same fixed directions as those of CelestialBody::non_rotating_reference_frame() of Orbit::body().

Note

For the orbit of a vessel, the origin is the point the vessel’s orbit has reached rather than the vessel’s own center of mass. The two are a few meters apart, as a vessel inside the physics bubble is simulated rather than being held on its orbit.

ReferenceFrame orbital_reference_frame()#

The reference frame that moves along the orbit, and is orientated with its prograde/normal/radial directions.

  • The origin is at the point the orbit has reached at the current time.

  • The axes rotate with the orbital prograde/normal/radial directions.

  • The x-axis points in the orbital anti-radial direction.

  • The y-axis points in the orbital prograde direction.

  • The z-axis points in the orbital normal direction.

Note

For the orbit of a vessel, the origin is the point the vessel’s orbit has reached rather than the vessel’s own center of mass, which is what Vessel::orbital_reference_frame() is centered on.
