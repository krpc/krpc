Lua Client Design#

The internal design of the Lua client. This page builds on the shared client design and the client specification. Usage is in the Lua guide. Paths are relative to client/lua/.

Ownership#

krpc.connect returns a Client table. The garbage collector tracks every holder, and an object holds its client through the methods of its class:

local function active_vessel()
  local conn = krpc.connect()
  return conn.space_center.active_vessel
  -- Holds the connection after conn goes out of scope
end

References#

The client holds its Connection, Types and service instances. The Connection holds the luasocket socket, and Types holds the class, enumeration and structure tables.

Each connection has its own Types, and so its own class tables. == compares object ids across connections. An object passed to another connection is rebuilt in that connection’s class.

The objects the program keeps also hold the client. An Object holds its class tables, whose method closures hold the Client. A service instance holds its service class, which also holds the Client.

The cycles are collected together. The socket’s finalizer is the only finalizer among these objects. Enumeration values hold no client. A structure holds one only through a field holding an object.

Lifetime#

  • The connection closes on close(), on a transport or protocol failure, or when the socket is collected.

  • close() closes the sending side of the socket, then drains it for up to a second.

  • After a close or a failure, Client._error holds the text, and a call through any holder raises it. A second close() does nothing.

  • Client has no __gc or __close. luasocket’s finalizer closes a collected socket, including at the end of the program, and sends no disconnect. An orderly close needs close().

Single Thread#

Calls follow the single-threaded design, on a blocking socket, so the client has no polling and no socket.select.

  • Only the handshake and the drain of a close have a socket timeout, as a luasocket timeout adds a cost to every call. A stalled message blocks a call, with no way to interrupt it.

  • No client code yields. A call blocks every coroutine in the Lua state, and two calls on one state do not interleave.

Dynamic Stubs#

The client has no generated code. Client:_init calls KRPC.GetServices, registers the types of every service, then builds each service, as a procedure can name a type from any service.

  • _construct_func compiles each procedure with load, into a function with fixed parameters. Arguments are read by position, so a nil leaves a hole and the later ones are still sent.

  • Service and class tables derive from Penlight’s class.properties. A property is a get_x and a set_x on the class table, reached through __index and __newindex.

  • A member naming a type this client does not know is skipped, with a warning on standard error, so a newer server still connects.

Server Side Functions#

The client has no function compiler, so a program builds a function with the expression API. There are no function streams or events, as the client has no streams.

  • The stub names the call. A Lua function has no name or parameter list to read, so _construct_func records each stub’s procedure in service.procedures. This covers a property’s get_x and set_x. get_call checks that one of a service’s properties is given the service, as a value in that position would otherwise be taken for it.

  • The procedure table holds no types. The keys of service.procedures are weak, and Lua 5.1 and LuaJIT have no ephemeron tables, so a value reaching a class table would keep the client alive. The types are on the client, by qualified name, so a stub from another connection encodes with this connection’s types.

  • The function supplies its types. run reads the types of the parameters and the value from the KRPC.Expression, through the connection running it, once per function. It caches them by object id. A null value is nil at any type.

Lua Versions#

The client runs on Lua 5.1 to 5.4 and LuaJIT. CI builds and tests on 5.4 only.

  • Version differences live in krpc/compat.lua and Penlight’s pl.compat. luacheck’s min std flags a global that any supported version lacks.

  • compat.native_integers picks the number model once, by whether math.type exists. The doubles of 5.1, 5.2 and LuaJIT are described in the guide’s Numeric Limits.

lua-protobuf#

  • lua-protobuf keeps types and options in one state per Lua state. The client loads its schema into a private state, and swaps it in with protobuf.call, so a script’s schemas and options stay separate. A response swaps once, for the message and its value together.

  • krpc/encoder.lua writes requests and collections by hand with pb.buffer, and krpc/decoder.lua reads collections with pb.slice, so a call builds no message tables.

Transports#

LocalConnection replaces only _open of the TCP/IP Connection.

  • socket.unix is required when the socket opens, so a luasocket without it still connects over TCP/IP. Stock luasocket lacks it on Windows, pending luasocket#469. The test build pins a luasocket that has it, so Windows CI covers connect_local.

  • The default socket path takes the user name from USER or LOGNAME, or on Windows from USERNAME, as Lua can only read the environment. With no user name, the connect raises an error.
