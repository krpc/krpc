Vessel#

Vessel

These objects are used to interact with vessels in KSP. This includes getting orbital and flight data, manipulating control inputs and managing resources. Created using GET /space-center/active-vessel or GET /space-center/vessels.

A Vessel object is passed and returned as its identifier, a number. A path that acts on an object takes it as (id).

GET /space-center/vessel/(id)/name#

The name of the vessel.

Parameters:

  • id – The identifier of the Vessel object.

Response JSON Object:

  • value (string)

PUT /space-center/vessel/(id)/name#

The name of the vessel.

Parameters:

  • id – The identifier of the Vessel object.

Request JSON Object:

  • value (string) – The new value.

GET /space-center/vessel/(id)/type#

The type of the vessel.

Parameters:

  • id – The identifier of the Vessel object.

Response JSON Object:

  • value (SpaceCenter.VesselType)

PUT /space-center/vessel/(id)/type#

The type of the vessel.

Parameters:

  • id – The identifier of the Vessel object.

Request JSON Object:

  • value (SpaceCenter.VesselType) – The new value.

GET /space-center/vessel/(id)/situation#

The situation the vessel is in.

Parameters:

  • id – The identifier of the Vessel object.

Response JSON Object:

  • value (SpaceCenter.VesselSituation)

GET /space-center/vessel/(id)/loaded#

Whether the vessel is loaded, i.e. its parts are instantiated in the scene because it is within loading range of the active vessel. A vessel that is not loaded exists only as orbital data and is always on-rails (see GET /space-center/vessel/(id)/packed).

Parameters:

  • id – The identifier of the Vessel object.

Response JSON Object:

  • value (bool)

GET /space-center/vessel/(id)/packed#

Whether the vessel is packed (on-rails). A packed vessel has its physics simulation suspended and follows its orbit analytically. A vessel that is not loaded (see GET /space-center/vessel/(id)/loaded) is always packed.

Parameters:

  • id – The identifier of the Vessel object.

Response JSON Object:

  • value (bool)

GET /space-center/vessel/(id)/physics-range#

The distance from the active vessel, in meters, out to which this vessel keeps running its physics simulation, and so stays controllable, able to burn its engines and respond to its autopilot. Setting this raises the vessel out of the stock physics bubble, so that it keeps flying while the active vessel is far away. Set to zero to restore the game’s default range.

Note

This always reports the vessel’s live range, so reading it when no range has been set gives the game’s default for the vessel’s current GET /space-center/vessel/(id)/situation, which is much shorter than the distance at which the vessel unloads. In orbit a vessel is put on rails just 350m away, long before it unloads at 2.5km, and a vessel on rails produces no thrust and ignores control input even though it is still loaded.

There is a 10% margin below the range, so that a vessel hovering at the threshold does not repeatedly drop out of the simulation and rejoin it. The vessel leaves the simulation at the distance set here, and rejoins it at 90% of that distance; in between it keeps whichever state it is already in.

The requested range applies in every situation. The game’s own defaults are not uniform, and a vessel flying in atmosphere stays loaded out to 22.5km, so setting a small range can shorten the range such a vessel would otherwise have had.

A range lasts until it is set back to zero or the game is exited. Unlike most state a client sets, it is not released when that client disconnects, because dropping a distant vessel back to the default range would put it on-rails part way through a maneuver.

Holding a vessel off-rails a long way from the active vessel costs performance, and accumulates positional error that can destroy it. Raise the range on the vessels that need it, by as little as they need.

Parameters:

  • id – The identifier of the Vessel object.

Response JSON Object:

  • value (float)

GET /space-center/vessel/(id)/recoverable#

Whether the vessel is recoverable.

Parameters:

  • id – The identifier of the Vessel object.

Response JSON Object:

  • value (bool)

POST /space-center/vessel/(id)/recover#

Recover the vessel. The crew return to the astronaut complex, and the funds and science the vessel is worth are awarded.

Note

Recovering the active vessel ends the flight and returns to the space center, as pressing recover in game does. When a non-active vessel is recovered the current scene is unaffected, and the mission completion dialog is not shown, so a script flying several vessels keeps control of the rest of them.

Returns immediately, does not wait for the vessel to be recovered.

Parameters:

  • id – The identifier of the Vessel object.

POST /space-center/vessel/(id)/terminate#

Terminate the vessel. The vessel and its parts are removed from the game, and its crew are lost, as when the vessel is terminated from the tracking station. Nothing is recovered: no funds, no science and no crew.

Note

The crew are reported missing, and return to the astronaut complex once their respawn timer expires, or never if the game is set up so that missing crews do not respawn.

The active vessel cannot be terminated, because the vessel being flown cannot be taken out of the scene it is being flown in. Switch to another vessel first, or use POST /space-center/vessel/(id)/recover, which ends the flight and returns to the space center.

Returns immediately, does not wait for the vessel to be terminated.

Parameters:

  • id – The identifier of the Vessel object.

GET /space-center/vessel/(id)/met#

The mission elapsed time in seconds.

Parameters:

  • id – The identifier of the Vessel object.

Response JSON Object:

  • value (double)

GET /space-center/vessel/(id)/launch-site#

The launch site the vessel was launched from, or null if the vessel was not launched from a known launch site, such as a vessel spawned by a contract.

Parameters:

  • id – The identifier of the Vessel object.

Response JSON Object:

  • value (SpaceCenter.LaunchSite?)

GET /space-center/vessel/(id)/biome#

The name of the biome the vessel is currently in.

Parameters:

  • id – The identifier of the Vessel object.

Response JSON Object:

  • value (string)

POST /space-center/vessel/(id)/flight#

Returns a Flight object that can be used to get flight telemetry for the vessel, in the specified reference frame.

Parameters:

POST /space-center/crew-member/(id)/eva#

Send the crew member outside on EVA, through the hatch of the part it is in, and return the vessel it becomes. The game switches to that vessel, which can then be walked around and flown using its GET /space-center/vessel/(id)/control, and brought back in with POST /space-center/control/(id)/board. The kerbal climbs out onto the ladder by the hatch, if there is one.

Note

Throws an exception if EVA is disabled for the game, if the crew member is not in a loaded vessel, if it is already on EVA, or if every hatch out of the part it is in is obstructed.

Parameters:

  • id – The identifier of the CrewMember object.

  • value (SpaceCenter.Vessel)
