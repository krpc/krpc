Streams and Events#

A script that follows the game reads the same values over and over. A stream has the server run a call on every physics tick and send you the result when it changes. An event has the server check a condition on every physics tick and tell you when it becomes true. Each client guide shows the syntax, for example streams in Python. This guide describes what the server does, which is the same for every client.

How Streams Update#

The server updates streams once per physics tick, after it has run that tick’s calls. So a stream sees what the calls did. It evaluates every stream of every client in the same pass, so the values in one update come from the same tick.

Each client receives at most one update message per tick, holding the streams whose value changed. When no value changed, the server sends nothing.

Each stream is separate. Streaming the same call twice runs it twice, and two clients never share a stream.

The first value of a new stream arrives in the tick the stream is created, just after the response that creates it. A call that takes several ticks to finish, such as SpaceCenter.WarpTo, gives its stream no value until it finishes.

Limiting the Rate#

A stream’s rate limits how many times a second the server updates it. The default, zero, updates it on every tick. This example updates a stream ten times a second:

altitude = conn.add_stream(getattr, flight, "mean_altitude")
altitude.rate = 10
while True:
    print(altitude())
    time.sleep(0.1)

var altitude = connection.AddStream (() => flight.MeanAltitude);
altitude.Rate = 10;
while (true) {
    Console.WriteLine (altitude.Get ());
    Thread.Sleep (100);
}

auto altitude = flight.mean_altitude_stream();
altitude.set_rate(10);
while (true) {
  std::cout << altitude() << std::endl;
  std::this_thread::sleep_for(std::chrono::milliseconds(100));
}

The C-nano client does not support streams.

Stream<Double> altitude =
    connection.addStream(flight, "getMeanAltitude");
altitude.setRate(10);
while (true) {
  System.out.println(altitude.get());
  Thread.sleep(100);
}

The Lua client does not support streams.

const altitude = await conn.addStream(() => flight.getMeanAltitude());
await altitude.setRate(10);
while (true) {
  console.log(await altitude.get());
  await new Promise((resolve) => setTimeout(resolve, 100));
}

The rate is a maximum, counted in real time rather than game time. A stream with a rate can therefore be a tick or more older than the other streams.

The Cost of a Stream#

A stream runs its call on every tick it is due. The server’s budget of time per frame limits its calls, but not its streams. Their time counts toward the budget, so many streams of expensive calls leave less time for calls. Past the budget, they slow every physics tick, and so the game.

Remove a stream once you no longer need it, or give it a rate. The server performance guide describes the settings.

The server ends the connection of a client that falls too far behind in reading its updates, as the protocol describes.

Events#

An event’s condition is a server side function that returns a boolean. The server checks it on every physics tick, so the event catches a condition that holds for a moment only, which a loop of calls can miss. This example waits for the vessel to climb above 10 km:

event = conn.add_event(lambda: flight.mean_altitude > 10000)
with event.condition:
    event.wait()
print("Above 10 km")

var evnt = connection.AddEvent (() => flight.MeanAltitude > 10000);
lock (evnt.Condition) {
    evnt.Wait ();
}
Console.WriteLine ("Above 10 km");

auto e = krpc::services::KRPC::Expression::bind(conn);
auto event = krpc::add_event(e.greater_than(
    e.call(flight.mean_altitude_call()), e.constant_double(10000)));
event.acquire();
event.wait();
event.release();
std::cout << "Above 10 km" << std::endl;

The C-nano client does not support events.

Expression.Bound e = Expression.bind(connection);
var event = connection.addEvent(e.greaterThan(
    e.call(connection.getCall(flight, "getMeanAltitude")),
    e.constantDouble(10000)));
synchronized (event.getCondition()) {
  event.waitFor();
}
System.out.println("Above 10 km");

The Lua client does not support events.

const event = await conn.addEvent(
  ({ flight }) => flight.meanAltitude > 10000,
  { flight },
);
await event.wait();
console.log("Above 10 km");

An event fires when its condition becomes true. It fires again each time the condition becomes true after being false, so a condition that stays true fires once. On the server, an event is a stream with a boolean value, and it is updated and removed in the same way.

How Streams End#

A stream ends when its call raises an exception, when you remove it, or when your connection closes. The client then raises the exception that ended it. Closing the connection removes all of its streams.

Two exceptions pause a stream instead of ending it: KRPC.ObjectNotLoadedException, for an object that is not loaded, and KRPC.UnsupportedSceneException, for a call that the current game scene does not support. A paused stream keeps its last value, and its updates resume once the object or the scene is available again. Loading a save or changing scene therefore pauses a stream of a remote call. The object lifetime guide describes when an object is not loaded.

A stream of a server side function, and an event, end on these exceptions instead of pausing. Create them again after the load.

An event that a service provides, rather than one you create, can also end when the service removes it.

Ticks and Pauses#

Streams do not update while a client holds the tick. The server sends their updates once the hold ends, so waiting for a stream or an event inside a hold waits until the hold times out.

While the game is paused, the server keeps running calls and updating streams. The Pause the server when the game pauses setting stops both until the game resumes.
